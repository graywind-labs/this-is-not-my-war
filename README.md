# 这不是我的战争

**[📄 阅读游戏作品介绍（PDF）](docs/这不是我的战争-游戏作品介绍Deck.pdf)**

> 玩家扮演一个边境驿站征兵官，想办法说服平民上战场、”鼓励”他们干活、不让他们当逃兵。

《这不是我的战争》是一款 AI 驱动的模拟经营防守游戏，参赛方向为「叙事重构·AI 沙盒与涌现式世界」。玩家管理一座即将遭到袭击的边境驿站：这里没有现成的军队，只有马夫、厨子、园丁、铁匠、老兵副官、神父、医生和工程师。你需要理解每个人的顾虑，用自然语言争取他们入伍、投入生产并留在防线上，最终组织这些普通人守住五波敌袭。

![边境驿站全景](docs/images/readme/01_station_overview.png)

## 产品定位

- **所选赛道：**叙事重构 ai沙盒与涌现式世界
- **一句话描述：**玩家扮演一个边境驿站征兵官，想办法说服平民上战场、”鼓励”他们干活、不让他们当逃兵。
- **玩法定位：**用AI NPC来增强模拟经营游戏里”人员管理“的乐趣，实质上是AI小镇的一种。
- **美术定位：**低模3D玩具风，轻量化而不廉价
- **题材定位：**西欧中世纪文艺复兴时期，参考1444年的西班牙地区
- **叙事定位：**无厘头黑色幽默表层+小人物的悲剧内核，从一个独特的视角看置身于战争中的普通人

## 核心玩法

### 1. 对话征召：想办法说服平民上战场

玩家可以查看 NPC 的职业、状态和已有经历，通过文字或语音与其交谈，针对人物的顾虑选择说服、利诱、威胁或其他表达方式。NPC 会结合人设、记忆和当前情境作出回应，并用动作、语气音效和 emoji 表达态度。

开局只有老兵副官艾达已经入伍，其余平民都需要逐个争取。应征者仍然是有意愿和判断的人，而不是可以直接操控的 RTS 单位。

![与厨子布鲁诺交涉并完成征召](docs/images/readme/02_recruitment_dialogue.png)

### 2. 士气与逃离：让已经上场的人愿意留下

征召成功只是开始。战斗触发、残血、疲劳和饥饿等关键节点会影响人物判断；玩家需要观察战时状态，通过交谈鼓舞、安抚或施压，并在 NPC 试图逃离时尝试挽留。战前承诺和战场现实都会进入后续判断上下文。

![逃离发生后的挽留与对话记录](docs/images/readme/04_escape_intervention.png)

### 3. 劳动力调配：“鼓励”他们干活

同一批人还要承担生产、治疗、训练和防守。玩家可以通过公告牌广播安排，与 NPC 交涉工作分工，并向已入伍者发布自然语言指令。NPC 根据指令、自身状态和记忆制定或局部修订计划，再由程序执行具体行动。

![格伦对工作安排提出异议](docs/images/readme/03_work_assignment.png)

### 4. 经营与防守：让人员管理接受战场检验

玩家需要生产和交易物资，升级或修复建筑，为入伍者配置武器、护甲与坐骑，部署箭塔和弩床，并在敌袭时拉响警铃。资源、生产、装备和建筑状态由程序进行权威结算；NPC 自动寻路、集结、索敌与战斗。人物生命归零后会昏迷而非死亡，可接受治疗并逐渐恢复。

五波敌军构成明确的阶段目标。玩家能否把普通人组织成一条防线，是此前所有交涉和经营决策的最终反馈。

![全员集结并在第四波敌袭中守住城门](docs/images/readme/05_wave_four_defense.png)

### 5. 记忆与关系：根据人物心理调整策略

每个 NPC 都有事件库、见闻库、第一人称日记和知识图谱。玩家可以查看人物亲历了什么、听说了什么以及如何理解他人，再据此调整后续对话与安排。征召、劳动和战斗会累积成连续的个人经历，从普通人的视角呈现战争的荒诞与压力。

## 游戏创意

1. **用迫近的守城战强化目标感。**敌袭为自由对话和日常经营提供清晰方向，玩家始终围绕争取人手、组织生产和准备防线作出决策。
2. **让对话承担实际玩法功能。**自然语言交互覆盖征召士兵、防止逃跑、鼓舞士气和调配劳动力，结果直接影响人手、生产和防线。
3. **增强情绪与即时反馈。**NPC 通过动作、语气音效和 emoji 表达情绪；语音输入同时识别玩家说了什么以及表达情绪，让说话方式成为交互的一部分。
4. **让经营与 NPC 决策相互影响。**经营决策通过事件系统进入 NPC 的认知；NPC 基于性格、状态和记忆作出的选择，又会改变玩家的人员与资源安排。
5. **强化模拟经营中的“管理者”幻想。**玩家面对的不是抽象岗位，而是诉求各异的人。怎样争取配合、兑现承诺并在战斗后调整管理方式，构成核心体验。

## AI NPC 技术实现

### 为 LLM 装上“眼睛”：信息空间与事件系统

项目为每个建筑建立信息空间，将人员、设施和状态转化为 LLM 可以理解的上下文。NPC 进入建筑时获得当前状态快照，空间发生变化时接收相应信息。

覆盖交互、经营与战斗的事件埋点，会把有意义的行为记录为结构化事件，并依据公开程度传播：私有事件只留给亲历者，同空间公开事件传递给当时在场的人，驿站公开事件广播给全站。接收者把信息写入见闻库；睡眠和昏迷会限制见闻接收。玩家与 AI、AI 与 AI 的对话也进入同一套短期记忆系统。

### 为 LLM 装上“手脚”：围绕计划的行动系统

系统在计划阶段向模型披露 NPC 能做的事情，把一天划分为 24 小时。NPC 跨天时生成新一天的完整计划，随后由确定性程序执行工作、进食、休息、训练等行动。正常情况下继续沿用原计划；只有行动失败时，才先判断需要修改的小时范围，再为这些时段生成替代计划。

高频空间执行由程序承担，LLM 专注于计划和关键决策。行动合法性、资源扣除、伤害与胜负都由程序校验和结算，既控制模型调用成本，也保留人物应对变化的灵活性。

### 分层记忆：短期经历、长期认知与根本人设

- **短期记忆：**事件库记录亲历，见闻库记录获知的信息；向模型提供时压缩重复内容并保留关键交互与结果。
- **长期记忆：**NPC 每日通过睡眠反思，把短期经历整理为第一人称日记并更新知识图谱。两者对玩家可见，也会参与之后的模型判断。
- **根本人设：**职业背景、性格、价值取向和基本诉求提供稳定参照，帮助角色在持续变化的经历中保持一致。

### 自动化空间执行

计划目标会被转换为具体建筑、工位和空间路线。角色使用 Godot 导航网格与 `NavigationAgent3D` 移动，结合动态避障和实体碰撞处理环境阻挡；进门时按实际到达顺序取得通行令牌；战斗时由程序根据行为模式、敌我关系、目标优先级、距离和可达性索敌，并按武器射程完成接近与攻击衔接。

```mermaid
flowchart LR
    A[玩家经营与对话] --> B[结构化事件]
    B --> C[信息空间与广播]
    C --> D[事件库 / 见闻库]
    D --> E[LLM 计划与关键判断]
    E --> F[确定性行动系统]
    F --> G[移动 / 工作 / 战斗]
    G --> B
    D --> H[每日反思]
    H --> I[日记 / 知识图谱]
    I --> E
```

## 技术栈

- **引擎：**Godot 4.6，Forward Plus，GDScript
- **AI 后端：**Python + Flask / Waitress
- **文本模型：**DeepSeek，支持玩家在设置中切换兼容服务
- **语音输入：**语音转写与情绪识别，经本地后端隔离凭据
- **数据驱动：**NPC、行动、建筑、资源、装备、敌军波次与 Prompt 均使用独立数据文件
- **资产管理：**Git LFS 管理正式模型、贴图、音频和 README 实机图
- **开发方式：**从策划案拆分任务，使用 Codex 与 Godot MCP 逐模块实现，并配套 Mock、真实 Provider、Godot headless 和发行构建验证

## 本地运行

### 依赖

- Git 与 [Git LFS](https://git-lfs.com/)
- Godot 4.6.x（项目发行基线为 4.6.2-stable）
- Python 3.11 或兼容版本

### 获取项目与 LFS 资源

```powershell
git clone https://github.com/graywind-labs/this-is-not-my-war.git
Set-Location this-is-not-my-war
git lfs install
git lfs pull
```

### 配置开发后端

```powershell
Copy-Item backend/.env.example backend/.env
python -m pip install -r backend/requirements.txt
python backend/app.py
```

在本机的 `backend/.env` 中填写所使用服务的 Key 和非秘密配置。该文件已被 Git 忽略；不要提交真实凭据。模型失败、无 Key 或 Schema 校验失败时，正式路径会明确返回错误，不会用 Mock 内容伪装成功。

后端启动后，用 Godot 4.6.x 导入根目录的 `project.godot` 并运行项目。主场景会先进入游戏主菜单。

### 构建 Windows 试玩版

```powershell
powershell -ExecutionPolicy Bypass -File tools/build_windows_demo.ps1
```

构建脚本会在隔离的临时工作区冻结后端并导出 Godot Release，生成一键启动的 Windows 试玩目录。详细配置、凭据边界和验收流程见 [试玩打包说明](docs/DEMO_PACKAGING.md)。
