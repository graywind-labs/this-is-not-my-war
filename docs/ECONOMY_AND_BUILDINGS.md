## 当前资源系统实现（T0202）

`res://scripts/systems/ResourceSystem.gd` 当前从 `data/resource_defs.json` 初始化基础资源，并提供最小读写接口：

- `get_resource(id)`：读取当前资源数量。
- `get_resource_definition(id)` / `get_resource_name(id)` / `get_resource_ids()`：读取资源定义、显示名和 UI 顺序。
- `add_resource(id, amount)`：增加或减少指定资源，结果不会低于配置的 `min_amount`。
- `can_afford(cost_dict)`：检查是否能支付一组资源成本。
- `spend_resources(cost_dict)`：资源足够时一次性扣除；任一资源不足时返回失败，不产生负数。

资源变化通过 `EventBus.resource_changed` 发出，`HUD.gd` 会按 `data/resource_defs.json.ui_order` 自动刷新显示非聚合资源。T0305 起新增派生资源 `meal` / 餐食、`wine` / 酒、`weapons` / 武器、`armor` / 盔甲、`defense_devices` / 工程器械、`horse_readiness` / 马匹整备；T0012 后，餐食和酒继续直接显示在 HUD 主资源栏，武器、盔甲、马匹整备和工程器械不在主栏重复显示。T0901 后，`weapons` / `armor` / `horse_readiness` 可由 `EquipmentSystem` 消耗并转换为已入伍 NPC 的装备槽；HUD 的“装备”详情按钮会展示这些聚合库存、可用装备定义和已分配数量，“器械”详情按钮会展示 `defense_devices` 工程器械库存。HUD 只读系统状态，不承担资源扣除、装备分配或器械部署结算。

## 当前行动结算实现（T0305）

`res://scripts/systems/ActionSystem.gd` 当前从 `data/action_defs.json` 读取最小行动定义，并复用 NPC 移动、资源系统、TimeSystem 逻辑时间和结构化事件完成工作 / 吃饭 / 睡觉闭环。行动到达目标地点后不会瞬时完成，而是进入 `current_action` 进行中状态，随 `logical_time_tick` 推进：

- 工作：调试接口 `debug_assign_work(npc_id, building_id)` 会安排 NPC 前往对应建筑，到达后开始持续工作。T0801 起，工作定义以 `duration_seconds` 作为单位周期基准，开始时通过 `BuildingSystem` 占用可进入建筑的真实工位；周期时长会按 NPC 对应熟练度、力量/智力属性和建筑等级缩短。单位周期完成时按行动配置扣除输入资源、增加输出资源，并调整饱食度和疲劳度；资源不足、行动中断或完成都会释放工位，并让地点信息节点广播内部工位变化。T0802 起，食堂的 `work_dining_hall` 使用厨艺，消耗 1 份粮食并产出 1 份餐食，厨艺、智力和食堂等级都会缩短加工周期。T0803 起，菜园的 `work_garden` 使用耕种和力量，基础产出 2 份粮食，并通过 `output_scaling` 让耕种熟练度、力量和菜园等级提高实际粮食产出；工作完成事件记录缩放后的实际 `output_resources`。T0804 起，铁匠铺的 `work_blacksmith` 使用打铁和力量，消耗 2 份铁并产出 1 份武器库存与 1 份盔甲库存；打铁、力量和铁匠铺等级影响制作周期。T0805 起，工械坊的 `work_workshop` 使用工程和智力，消耗 2 份木材并产出 1 份武器库存与 1 份工程器械库存；工程、智力和工械坊等级影响制作周期。T0806 起，马厩的 `work_stable` 使用养马和力量，消耗 1 份粮食并产出 `horse_readiness` 马匹整备库存，养马、力量和马厩等级会缩短照料周期并提高实际整备产出。T0807 起，酒窖的 `work_tavern` 使用酿酒和智力，消耗 1 份粮食并产出 `wine` 酒库存，酿酒、智力和酒窖等级会缩短酿造周期并提高实际酒产出。T0904 起，工作完成会以很慢速度提升行动配置对应职业熟练度，并同步增加 NPC 总经验；经验达标产生未分配技能点。当前调试指派默认执行 1 个工作单位，已覆盖菜园产粮、食堂加工餐食、酒窖酿酒、铁匠铺制造武器/盔甲库存、工械坊制造弓弩/工程器械库存和马厩维护马匹整备。后续各职业任务会继续细化资源平衡和特殊逻辑。
- 协助修复：`debug_assign_repair_assist(npc_id, building_id)` 是带建筑参数的独立行为，会让 NPC 前往正在修复的建筑，到达后按工程熟练度为该建筑修复倒计时增加速度倍率；多个 NPC 可同时协助。协助修复不再作为 `data/action_defs.json` 里的固定“修补某建筑”行动配置。
- 协助升级：`debug_assign_upgrade_assist(npc_id, building_id)` 是带建筑参数的独立行为，会让 NPC 前往广场，到达后按工程熟练度为正在升级的建筑倒计时增加速度倍率；多个 NPC 可同时协助。
- 协助治疗：`debug_assign_heal_assist(healer_npc_id, target_npc_id)` 是带昏迷 NPC 目标的独立行为，会让治疗者前往目标所在信息地点；每个昏迷目标最多 2 名治疗者。治疗开始立即消耗 1 枚第纳尔，持续治疗期间每 1800 游戏秒继续消耗 1 枚第纳尔；医术熟练度影响额外 HP 恢复速度，低医术几乎没有额外加成，高医术明显快于自然恢复。
- 小诊所治疗：T0808 起，小诊所拥有医生工位 `clinic_doctor` 和病床 `patient_bed`。`work_clinic_doctor` 让 NPC 占用医生工位坐诊；没有病人占床时，医生会以很慢节奏研读医学著作并提升医术。`receive_clinic_treatment` 让受伤且未昏迷 NPC 占用病床；只有医生在岗且病人占床时才推进诊所治疗。治疗按逻辑时间消耗第纳尔并恢复病人 HP，治疗速度由医术、智力和小诊所等级共同提高；病人 HP 回满后释放病床并写入治疗完成事件。
- 训练场训练：T0903 起，训练场拥有教官工位 `training_instructor` 和受训位 `training_student`。`work_training_instructor` 让有主武器或坐骑的 NPC 占用教官工位；`receive_weapon_training` 让有主武器或坐骑的 NPC 在已有教官时占用受训位。教官无受训者时极慢提升自己当前装备对应的剑盾、长杆、弓、弩或骑术；有受训者时，受训者按自己的当前主武器 / 坐骑提升对应熟练度，教官提升“教练”。训练速度受教官“教练”、训练场等级、以及教官和受训者在当前训练项目上的熟练度差影响；训练按单位时间消耗疲劳和饱食。T0904 后训练增长也同步增加经验和未分配技能点。
- 吃饭：`debug_assign_eat(npc_id)` 会安排 NPC 前往食堂，优先消耗餐食并在 20 分钟内逐步恢复 50 点饱食度；无餐食时消耗粮食并恢复 25 点饱食度。
- 睡觉：`debug_assign_sleep(npc_id)` 会安排 NPC 前往宿舍，按 6.5 小时消耗 100 点疲劳的基准逐步降低疲劳度，并轻微消耗饱食度。
- 行动完成或失败会写入 `MemorySystem` 的 EventLog 占位。

当前只实现统一工作产出框架、占位数值、诊所治疗闭环、训练场熟练度提升、T0901 装备库存转换、T0902 兵种判定、T0904 通用经验 / 技能点与玩家分配力量 / 智力调试接口，不实现 LLM 日程、各职业特殊生产平衡、完整战斗、器械部署或商人交易。T0805 的弓/弩仍先进入通用 `weapons` 派生库存，T0901 已允许装备系统把该库存转换为剑盾、长杆、弓或弩等主武器，T0902 已按装备槽判定对应兵种；工程器械先进入 `defense_devices` 派生库存，部署由 T1508 处理。T0806 的马匹恢复/再生产先进入通用 `horse_readiness` 派生库存，T0901 已允许其转换为坐骑槽；T0902 明确只有 NPC 的 `equipment.mount` 槽会影响骑兵判定，库存本身不会。T1103 已接入集结 / 接敌时的低模坐骑显示，日常工作不骑乘；T1105 已让坐骑影响近战骑兵 / 骑射单位的可选战斗策略，更完整的移动速度加成仍留给后续战斗移动数值任务。T0807 的酒先进入 `wine` 派生库存，出售换第纳尔由 T1507 商人交易系统处理，不在酒窖工作完成时自动换钱。

资源产出/消耗、饱食/疲劳变化、治疗和建筑修复等与时间相关的结算，应使用 TimeSystem 的有效逻辑时间倍率。玩家 `x2` / `x4` 加速时，工作 / 日常结算同步加快；LLM 等待造成慢速时，结算同步减缓。T1104A 起，若场景中存在活动敌人，TimeSystem 有效倍率上限会被 CombatSystem 压到 `x1`，因此敌人在场期间工作 / 日常结算也不会超过 `x1`。暂停时相关结算不推进；尚未到达目标地点的行动保持 pending，已经开始的行动保持 active，恢复后继续。该倍率不改变 NPC 移动速度或动画速度，也不作为战斗伤害、攻速或战斗移动速度的额外倍率。

## 当前建筑系统实现（T0203）

`res://scripts/systems/BuildingSystem.gd` 当前从 `data/building_defs.json` 初始化建筑基础状态，并绑定到 `Main.tscn` 中已有的低模建筑节点。

公告牌不属于建筑系统。`Main.tscn` 中的 `NoticeBoard` 只是挂在主厅前的视觉占位和后续公告输入入口，不在 `data/building_defs.json` 中配置 HP、等级、工作位、修复、升级或建筑点击结算。公告文本的权威状态由广场信息节点保存，并通过 `MemorySystem.set_plaza_notice(...)` / GM 的广场公告入口写入。

当前支持：

- 读取建筑 `id`、名称、等级、HP / Max HP、标签、工作位、资源输入输出和 `scene_nodes` 绑定。
- 为每个绑定的低模建筑运行时创建 `Area3D` 点击区，点击后记录当前选中建筑并发出 `EventBus.building_clicked(building_id)`。
- 建筑受损、修复进度、协助者变化、修复完成和升级只发出 `EventBus.building_state_changed(building_id)` 供当前可见面板刷新，不复用 `building_clicked`，避免状态刷新抢占玩家当前查看的 NPC 面板。
- 将建筑调试标签更新为名称、等级和 HP，用于 T0203 阶段确认基础状态。
- 提供 `get_building(id)`、`get_building_ids()`、`get_building_snapshot()` 和 `debug_select_building(id)` 供后续 UI/测试使用。

T0205 后，`BuildingSystem.gd` 增加建筑修复与升级的最小闭环；2026-05-24 已将修复从“瞬间恢复 HP”改为“预付资源后的倒计时修复”：

- `can_repair_building(id)` / `repair_building(id)`：所有建筑都应具备 `repair` 配置；仅当建筑 HP 低于 Max HP、没有正在进行的修复/升级、存在 `repair.cost` 配置且资源足够时可执行；点击修复时一次性扣除资源并创建修复作业，不立刻回满 HP。
- 修复时长由缺失 HP、建筑等级和 `repair.seconds_per_missing_hp` / `repair.level_time_factor` 决定；缺失 HP 越多、等级越高，修复倒计时越长。
- 修复进行中，建筑 HP 会随逻辑时间逐步提高；暂停时不推进，玩家加速或 LLM 减速会通过 TimeSystem 的 `logical_time_tick` 同步影响修复速度。
- NPC 可通过协助修复行为加入正在进行的修复作业；每名协助者按工程熟练度提供一个小额速度加成，多个 NPC 加成可叠加。协助者必须仍处于广场且当前行动为该建筑的协助修复；若 NPC 离开广场或被改派做别的事，其协助人数和速度加成立即移除。修复完成后仍在协助的 NPC 自动回到 idle。
- `can_upgrade_building(id)` / `upgrade_building(id)`：仅当建筑未达到 `upgrade.max_level`、存在 `upgrade.cost` 且资源足够时可执行；升级会提升等级，并按配置增加 Max HP 和可选工作位。
- `debug_damage_building(id, amount)`：临时验证入口，用于在战斗系统未实现前模拟建筑受损。
- 修复/升级资源扣除统一调用 `ResourceSystem.spend_resources`；资源不足时不会扣资源，也不会改变建筑 HP、等级或工作位。
- 建筑调试标签会在修复推进、修复完成或升级后刷新 HP 和等级。
- 每次 `building_state_changed` 由 `MemorySystem` 同步为字段级状态见闻：广场保存所有建筑外部状态，但广播时只传递发生变化的外部字段；可进入建筑保存完整外部 + 内部状态，但后续广播只传递变化字段，例如建筑受损、升级完成或单个工位占用变化。人员进出不再触发完整内部状态广播，而由 `location_entered` / `location_exited` 本地公开事件表达。

当前 `data/building_defs.json` 已为主厅、宿舍、食堂、仓库、围墙加入 `repair` / `upgrade` 配置；围墙升级会增加 1 个修复工作位，用于验证升级至少影响一个非 HP 数值。其余建筑可在后续平衡任务中逐步补齐配置。当前仍不实现生产、敌人攻击或美术变化。

## 当前建筑面板实现（T0204）

`res://scripts/ui/BuildingPanel.gd` 当前绑定到 `Main/UI/BuildingPanel`，监听 `EventBus.building_clicked(building_id)` 打开被点击建筑，并监听 `EventBus.building_state_changed(building_id)` 刷新当前可见的对应建筑状态。

当前支持：

- 显示建筑名称、等级、HP / Max HP。
- T0016 后不再显示单独的“当前工作位 x/x”汇总行；工位、床位和训练位按 `workstations` 真实数组中的 `type` 分组，显示 `空闲数/总数：占用者`。无占用者显示“空闲”，有占用者时显示 NPC 名字，诊所、训练场等多类型建筑会分行显示各自容量。
- 显示地点信息占位，当前展示建筑标签和正在修复时的进度/剩余时间/协助人数；建筑面板不展示建筑保存的历史事件。
- 如果修复过程中玩家点击 NPC，建筑状态刷新不会重新显示建筑面板；玩家需要再次点击建筑才会切回建筑面板。
- 显示修复、升级按钮；T0205 后按钮会调用 `BuildingSystem` 的修复/升级接口，并根据 HP、等级和资源是否足够自动启用或禁用。修复/升级资源消耗和条件不在面板正文常驻展示，只在鼠标悬停按钮时显示在按钮旁提示框中。
- 关闭按钮可隐藏面板；未知建筑或无建筑时面板保持隐藏。

当前不实现生产结算、储存消耗展示或敌人攻击；修复与升级已经具备最小可用逻辑，后续仍需补齐更多建筑的配置和平衡数值。

T0004 后，GM 面板已提供资源与建筑调试入口，可在 `Main.tscn` 中直接增加/扣除资源、查看资源快照、选中建筑、模拟建筑受损、触发修复/升级和查看建筑快照。GM 面板不承担资源或建筑权威结算，只调用 `ResourceSystem` 与 `BuildingSystem` 现有接口。

## 地点进入与信息节点边界

建筑不都等同于可进入地点。所有建筑都有外部状态；只有可进入建筑拥有内部状态。

可进入地点包括宿舍、食堂、酒窖、菜园、铁匠铺、训练场、马厩、小教堂、小诊所、工械坊和广场。NPC 可以进入这些地点；这些地点维护信息节点，记录建筑外部状态、可进入建筑内部状态、当前在场 NPC 状态、工作位/床位占用和当前公告/命令。在场 NPC 状态分为生命状态和行动状态：生命状态只表达健康、受伤、昏迷，以及昏迷时是否有人正在治疗；行动状态从 `current_action` 翻译成精简中文。信息节点只负责状态读取与公开事件即时转运，不保存事件历史；除 NPC 进入地点时给进入者的一次性快照外，状态变化只广播变化字段。

主厅、围墙、城门、后门、仓库属于不可进入实体。它们仍有 HP、等级、修复/升级、受损和摧毁等权威外部状态，但不作为 NPC 常规进入地点，也不暴露工位、床位和内部 NPC 状态。它们的外部状态归入广场信息节点。

广场是特殊地点，没有建筑 HP；所有室外事件默认归入广场。广场信息节点聚合室外人员、室外人员的生命/行动状态、当前公告文本、当前战斗状态，以及所有建筑的可传播外部状态。任一建筑的可传播外部状态变化时，广场保存的外部状态同步更新，并通过广场节点把变化字段即时广播给当时在场的 NPC，广播后广场不保存事件历史。

当前 T0403 已在 `MemorySystem` 中实现地点信息节点的数据闭环：

- 可进入地点的信息节点维护 `people_present`、当前公告/命令和进入快照。
- NPC 到达可进入地点时，旧地点移除该 NPC，新地点加入该 NPC，并写入 `location_entered` 行动事件；该事件只表达“进入某地”，完整地点状态不再重复进入事件库。
- 进入者会在见闻库获得一次当前状态快照：进入可进入建筑时包含当前在场 NPC、建筑内 NPC 的生命状态/行动状态、建筑等级、完好/受损/正在修复/正在升级、工位占用字段和当前公告/命令；进入广场时包含当前广场在场 NPC、广场在场 NPC 的生命状态/行动状态、当前公告文本和所有建筑的可传播外部状态。建筑 HP、剩余修复/升级时长和工位数量不作为需要广播的状态字段。
- NPC 离开地点时写入 `location_exited` 行动事件，事件地点为其离开的地点，并以 `local_public` 转发给仍在该地点的 NPC；离开事件不附带完整地点状态。
- `BuildingSystem.get_building_location_context(...)` 当前优先读取 `MemorySystem.get_location_snapshot(...)`，因此 UI 和 NPC 状态看到的是同一套当前状态快照。
- 主厅、围墙、城门、后门、仓库仍不作为常规进入地点；其状态归入广场信息节点。
- 地点信息节点只保存当前状态，不保存事件历史；`local_public` 事件由 `MemorySystem` 即时转发给当前在场 NPC 的见闻库。NPC 进入可进入建筑会获得该建筑完整当前状态见闻；NPC 进入广场会获得当前广场在场 NPC、这些 NPC 的生命状态/行动状态、当前公告文本和所有建筑外部状态见闻。已经在场的 NPC 通过进入/离开事件得知人员变化，不再额外收到完整 `people_present` 或 `people_statuses` 状态。

## 建筑通用属性

| 属性 | 说明 |
|---|---|
| 建筑等级 | 影响产出、容量、效率或防御能力 |
| 建筑生命值 | 被攻击时下降，归零后失效或摧毁 |
| 完好/受损/正在修复/正在升级 | 由 HP、修复作业和升级作业决定；这是 NPC 见闻传播的建筑状态口径 |
| 工作位数量 | 仅可进入建筑拥有；可同时进行相关工作的 NPC 数量 |
| 当前占用状态 | 仅可进入建筑拥有；哪些工作位被谁占用、哪些空闲 |
| 在场 NPC | 广场和可进入建筑拥有；当前在该地点信息节点中的 NPC |
| 在场 NPC 状态 | 广场和可进入建筑的进入者快照中可见，生命状态为健康/受伤/昏迷，行动状态为当前行动的精简中文 |
| 信息节点 | 保存地点/建筑当前状态和当前占用，并向在场 NPC 广播公开事件；公告/命令文本只由广场当前状态保存，不作为普通建筑属性；不保存事件历史 |

## 建筑修复与升级

所有建筑都可以修复，也都有升级潜力。升级和修复一样是随 `TimeSystem.logical_time_tick` 推进的倒计时作业：玩家开始升级时由 `ResourceSystem` 一次性扣除资源，倒计时结束后才提升建筑等级并应用 Max HP 或工作位等奖励。建筑受损时不可升级，正在修复时不可升级，正在升级时不可修复；只有完好且未处于修复/升级作业中的建筑才能开始升级。

NPC 可通过行动系统协助正在修复或正在升级的建筑。协助修复与协助升级都是广场/室外行为：NPC 已在广场时可直接协助；NPC 在室内时需要先移动到广场。协助事件的 `location_id` 为 `plaza`，`visibility` 为 `local_public`。NPC 离开广场或被改派后，加速人数和倍率立即从作业中移除。

NPC 从一个室内工作/生活地点切换到另一个室内地点时，信息系统按“原地点 -> 广场 -> 目标地点”的逻辑链记录进出事件；当前低模移动表现仍可使用直线占位，后续更精细导航只负责替换表现层路径。

可传播建筑状态只计算建筑等级和 `condition`（`intact` / `damaged` / `repairing` / `upgrading`）。HP、Max HP、剩余修复时长和剩余升级时长仍是建筑系统和 UI 可读取的权威数据，但不再作为信息节点变化传播条件。广场和可进入建筑的在场 NPC 列表及其生命/行动状态只在某个 NPC 进入该地点时作为完整快照传给进入者；对已经在场的 NPC，人员变化由进入/离开事件表达。可进入建筑的其他内部状态变化只广播变化字段，例如某个工位从空闲变为占用；工位数量本身不触发传播。
