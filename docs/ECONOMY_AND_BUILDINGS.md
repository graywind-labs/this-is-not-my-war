## 当前资源系统实现（T0202）

`res://scripts/systems/ResourceSystem.gd` 当前从 `data/resource_defs.json` 初始化基础资源，并提供最小读写接口：

- `get_resource(id)`：读取当前资源数量。
- `add_resource(id, amount)`：增加或减少指定资源，结果不会低于配置的 `min_amount`。
- `can_afford(cost_dict)`：检查是否能支付一组资源成本。
- `spend_resources(cost_dict)`：资源足够时一次性扣除；任一资源不足时返回失败，不产生负数。

资源变化通过 `EventBus.resource_changed` 发出，`HUD.gd` 会自动刷新显示基础五类资源。T0305 起新增派生资源 `meal` / 餐食、`wine` / 酒、`weapons` / 武器、`armor` / 盔甲、`defense_devices` / 工程器械、`horse_readiness` / 马匹整备，当前不显示在 HUD 中，只供行动系统内部结算使用。

## 当前行动结算实现（T0305）

`res://scripts/systems/ActionSystem.gd` 当前从 `data/action_defs.json` 读取最小行动定义，并复用 NPC 移动、资源系统、TimeSystem 逻辑时间和结构化事件完成工作 / 吃饭 / 睡觉闭环。行动到达目标地点后不会瞬时完成，而是进入 `current_action` 进行中状态，随 `logical_time_tick` 推进：

- 工作：调试接口 `debug_assign_work(npc_id, building_id)` 会安排 NPC 前往对应建筑，到达后开始持续工作。当前工作定义以 1 小时为最小批次，批次结束时按行动配置扣除输入资源、增加输出资源，并调整饱食度和疲劳度。当前已覆盖菜园产粮、食堂加工餐食、酒窖酿酒、铁匠铺制造武器/盔甲、工械坊制造工程器械和马厩产出马匹整备占位。后续 T0801 会继续细化工作位占用、职业效率和资源平衡。
- 协助修复：`debug_assign_repair_assist(npc_id, building_id)` 是带建筑参数的独立行为，会让 NPC 前往正在修复的建筑，到达后按工程熟练度为该建筑修复倒计时增加速度倍率；多个 NPC 可同时协助。协助修复不再作为 `data/action_defs.json` 里的固定“修补某建筑”行动配置。
- 吃饭：`debug_assign_eat(npc_id)` 会安排 NPC 前往食堂，优先消耗餐食并在 20 分钟内逐步恢复约 50 点饱食度；无餐食时消耗粮食并恢复较少饱食度。
- 睡觉：`debug_assign_sleep(npc_id)` 会安排 NPC 前往宿舍，按 6.5 小时消耗 100 点疲劳的基准逐步降低疲劳度，并轻微消耗饱食度。
- 行动完成或失败会写入 `MemorySystem` 的 EventLog 占位。

当前只实现占位数值和调试接口，不实现 LLM 日程、复杂职业效率、训练、战斗、装备库存细分、器械部署或工作位占用。

资源产出/消耗、饱食/疲劳变化、治疗和建筑修复等与时间相关的结算，应使用 TimeSystem 的有效逻辑时间倍率。玩家 `x2` / `x4` 加速时数值结算同步加快；LLM 等待造成慢速时，数值结算同步减缓。暂停时相关结算不推进；尚未到达目标地点的行动保持 pending，已经开始的行动保持 active，恢复后继续。该倍率不改变 NPC 移动速度或动画速度。

## 当前建筑系统实现（T0203）

`res://scripts/systems/BuildingSystem.gd` 当前从 `data/building_defs.json` 初始化建筑基础状态，并绑定到 `Main.tscn` 中已有的低模建筑节点。

公告牌不属于建筑系统。`Main.tscn` 中的 `NoticeBoard` 只是挂在主厅前的视觉占位和后续公告输入入口，不在 `data/building_defs.json` 中配置 HP、等级、工作位、修复、升级或建筑点击结算。公告文本的权威状态由广场信息节点保存，并通过 `MemorySystem.set_plaza_notice(...)` / GM 的广场公告入口写入。

当前支持：

- 读取建筑 `id`、名称、等级、HP / Max HP、标签、工作位、资源输入输出和 `scene_nodes` 绑定。
- 为每个绑定的低模建筑运行时创建 `Area3D` 点击区，点击后记录当前选中建筑并发出 `EventBus.building_clicked(building_id)`。
- 建筑受损、修复进度、协助者变化、修复完成和升级只发出 `EventBus.building_state_changed(building_id)` 供当前可见面板刷新，不复用 `building_clicked`，避免状态刷新抢占玩家当前查看的 NPC 面板。
- 将建筑调试标签更新为名称、等级和 HP，用于 T0203 阶段确认基础状态。
- 提供 `get_building(id)`、`get_building_ids()`、`get_building_snapshot()` 和 `debug_select_building(id)` 供后续 UI/测试使用。

T0205 后，`BuildingSystem.gd` 增加建筑修复与升级的最小闭环；2026-05-24 已将修复从“瞬间恢复 HP”改为“预付资源后的倒计时修复”：

- `can_repair_building(id)` / `repair_building(id)`：所有建筑都应具备 `repair` 配置；仅当建筑 HP 低于 Max HP、没有正在进行的修复/升级、存在 `repair.cost` 配置且资源足够时可执行；点击修复时一次性扣除资源并创建修复作业，不立刻回满 HP。
- 修复时长由缺失 HP、建筑等级和 `repair.seconds_per_missing_hp` / `repair.level_time_factor` 决定；缺失 HP 越多、等级越高，修复倒计时越长。
- 修复进行中，建筑 HP 会随逻辑时间逐步提高；暂停时不推进，玩家加速或 LLM 减速会通过 TimeSystem 的 `logical_time_tick` 同步影响修复速度。
- NPC 可通过协助修复行为加入正在进行的修复作业；每名协助者按工程熟练度提供一个小额速度加成，多个 NPC 加成可叠加。协助者必须仍处于广场且当前行动为该建筑的协助修复；若 NPC 离开广场或被改派做别的事，其协助人数和速度加成立即移除。修复完成后仍在协助的 NPC 自动回到 idle。
- `can_upgrade_building(id)` / `upgrade_building(id)`：仅当建筑未达到 `upgrade.max_level`、存在 `upgrade.cost` 且资源足够时可执行；升级会提升等级，并按配置增加 Max HP 和可选工作位。
- `debug_damage_building(id, amount)`：临时验证入口，用于在战斗系统未实现前模拟建筑受损。
- 修复/升级资源扣除统一调用 `ResourceSystem.spend_resources`；资源不足时不会扣资源，也不会改变建筑 HP、等级或工作位。
- 建筑调试标签会在修复推进、修复完成或升级后刷新 HP 和等级。
- 每次 `building_state_changed` 由 `MemorySystem` 同步为字段级状态见闻：广场保存所有建筑外部状态，但广播时只传递发生变化的外部字段；可进入建筑保存完整外部 + 内部状态，但后续广播只传递变化字段，例如建筑受损、升级完成或单个工位占用变化。人员进出不再触发完整内部状态广播，而由 `location_entered` / `location_exited` 本地公开事件表达。

当前 `data/building_defs.json` 已为主厅、宿舍、食堂、仓库、围墙加入 `repair` / `upgrade` 配置；围墙升级会增加 1 个修复工作位，用于验证升级至少影响一个非 HP 数值。其余建筑可在后续平衡任务中逐步补齐配置。当前仍不实现生产、敌人攻击或美术变化。

## 地点进入与信息节点边界

建筑不都等同于可进入地点。所有建筑都有外部状态；只有可进入建筑拥有内部状态。

可进入地点包括宿舍、食堂、酒窖、菜园、铁匠铺、训练场、马厩、小教堂、小诊所、工械坊和广场。NPC 可以进入这些地点；这些地点维护信息节点，记录建筑外部状态、可进入建筑内部状态、工作位/床位占用和当前公告/命令。信息节点只负责状态读取与公开事件即时转运，不保存事件历史；除 NPC 进入地点时给进入者的一次性快照外，状态变化只广播变化字段。

主厅、围墙、城门、后门、仓库属于不可进入实体。它们仍有 HP、等级、修复/升级、受损和摧毁等权威外部状态，但不作为 NPC 常规进入地点，也不暴露工位、床位和内部 NPC 状态。它们的外部状态归入广场信息节点。

广场是特殊地点，没有建筑 HP；所有室外事件默认归入广场。广场信息节点聚合室外人员、当前公告文本、当前战斗状态，以及所有建筑的可传播外部状态。任一建筑的可传播外部状态变化时，广场保存的外部状态同步更新，并通过广场节点把变化字段即时广播给当时在场的 NPC，广播后广场不保存事件历史。

当前 T0403 已在 `MemorySystem` 中实现地点信息节点的数据闭环：

- 可进入地点的信息节点维护 `people_present`、当前公告/命令和进入快照。
- NPC 到达可进入地点时，旧地点移除该 NPC，新地点加入该 NPC，并写入 `location_entered` 行动事件；该事件只表达“进入某地”，完整地点状态不再重复进入事件库。
- 进入者会在见闻库获得一次当前状态快照：进入可进入建筑时包含当前在场 NPC、建筑等级、完好/受损/正在修复/正在升级、工位占用字段和当前公告/命令；进入广场时额外包含所有建筑的可传播外部状态。建筑 HP、剩余修复/升级时长和工位数量不作为需要广播的状态字段。
- NPC 离开地点时写入 `location_exited` 行动事件，事件地点为其离开的地点，并以 `local_public` 转发给仍在该地点的 NPC；离开事件不附带完整地点状态。
- `BuildingSystem.get_building_location_context(...)` 当前优先读取 `MemorySystem.get_location_snapshot(...)`，因此 UI 和 NPC 状态看到的是同一套当前状态快照。
- 主厅、围墙、城门、后门、仓库仍不作为常规进入地点；其状态归入广场信息节点。
- 地点信息节点只保存当前状态，不保存事件历史；`local_public` 事件由 `MemorySystem` 即时转发给当前在场 NPC 的见闻库。NPC 进入可进入建筑会获得该建筑完整当前状态见闻；NPC 进入广场会获得所有建筑外部状态见闻。已经在场的 NPC 通过进入/离开事件得知人员变化，不再额外收到完整 `people_present` 状态。

## 建筑通用属性

| 属性 | 说明 |
|---|---|
| 建筑等级 | 影响产出、容量、效率或防御能力 |
| 建筑生命值 | 被攻击时下降，归零后失效或摧毁 |
| 完好/受损/正在修复/正在升级 | 由 HP、修复作业和升级作业决定；这是 NPC 见闻传播的建筑状态口径 |
| 工作位数量 | 仅可进入建筑拥有；可同时进行相关工作的 NPC 数量 |
| 当前占用状态 | 仅可进入建筑拥有；哪些工作位被谁占用、哪些空闲 |
| 建筑内 NPC | 仅可进入建筑拥有；当前在该建筑信息节点中的 NPC |
| 信息节点 | 保存地点/建筑当前状态和当前占用，并向在场 NPC 广播公开事件；公告/命令文本只由广场当前状态保存，不作为普通建筑属性；不保存事件历史 |

## 建筑修复与升级

所有建筑都可以修复，也都有升级潜力。升级和修复一样是随 `TimeSystem.logical_time_tick` 推进的倒计时作业：玩家开始升级时由 `ResourceSystem` 一次性扣除资源，倒计时结束后才提升建筑等级并应用 Max HP 或工作位等奖励。建筑受损时不可升级，正在修复时不可升级，正在升级时不可修复；只有完好且未处于修复/升级作业中的建筑才能开始升级。

NPC 可通过行动系统协助正在修复或正在升级的建筑。协助修复与协助升级都是广场/室外行为：NPC 已在广场时可直接协助；NPC 在室内时需要先移动到广场。协助事件的 `location_id` 为 `plaza`，`visibility` 为 `local_public`。NPC 离开广场或被改派后，加速人数和倍率立即从作业中移除。

可传播建筑状态只计算建筑等级和 `condition`（`intact` / `damaged` / `repairing` / `upgrading`）。HP、Max HP、剩余修复时长和剩余升级时长仍是建筑系统和 UI 可读取的权威数据，但不再作为信息节点变化传播条件。可传播内部状态只计算建筑内 NPC 列表和每个工位的空闲/占用者，工位数量本身不触发传播。建筑内 NPC 列表只在某个 NPC 进入该建筑时作为完整快照传给进入者；对已经在场的 NPC，人员变化由进入/离开事件表达。其他内部状态变化只广播变化字段，例如某个工位从空闲变为占用。

NPC HP 恢复到 30% 后复苏。

## 仓库

储藏资源。  
敌人攻击仓库会造成资源流失。  
仓库等级影响容量和被掠夺损失比例。

## 围墙

敌人攻入驿站前需要先破坏围墙或城门。  
可消耗石料修复或升级。  
工程器械可部署在围墙上。
