# SAVE_SYSTEM.md

## 1. 目标与范围

T0355 使用“波次结束检查点”，不提供任意时刻世界捕获。

- 正式开局完成时生成第 0 检查点。
- 每次正式敌人全部清空、战斗清理完成后生成自动检查点。
- 手动保存只复制最近一次已校验的自动检查点，不读取当前运行世界。
- 一个游戏档案使用永久 `archive_id`。自动检查点只覆盖同一 `archive_id` 的 `auto`，绝不覆盖其 `manual`。
- 另存到其他槽位时生成新的 `archive_id`，避免后续自动保存跨档覆盖。

这个边界允许制造、移动、对话、反思和战斗表现相位统一回滚；已经结算或已经支付的权威事实必须保存。

## 2. 磁盘模型

```text
user://saves/
├─ index.json
└─ archives/<archive_id>/
   ├─ auto/
   │  ├─ meta.json
   │  ├─ state.json
   │  └─ thumbnail.webp
   └─ manual/
      ├─ meta.json
      ├─ state.json
      └─ thumbnail.webp
```

`index.json` 只保存稳定槽位到 `archive_id` 的映射和最后活动档案，不保存玩法状态。`meta.json` 可独立读取；`state.json` 保存完整权威快照。有渲染窗口时，自动检查点同时从最终 Main 视口生成 `480×270`、16:9、质量 0.82 的 WebP，并在元数据记录独立 SHA-256；缩略图缺失或损坏不阻止加载。

写入先落到同目录临时文件，完成 JSON 解析、Schema 和 SHA-256 校验后再替换正式文件。高于客户端支持版本、校验失败或 JSON 损坏的恢复点仍显示，但禁止加载并给出原因。

## 3. 玩家交互

- “继续游戏”加载最后活动档案的最新有效 `auto`。
- 存档浏览器每个档案可选择“最新自动检查点”或“玩家固定检查点”。
- 详情区显示所选恢复点自身的缩略图；切换 auto / manual 时同步切图。旧档、headless 检查点或损坏图片显示占位。
- 游戏内“快速保存”文案改为“固定最近检查点”；它与普通手动槽一样只复制最近 `auto`。
- 保存详情必须显示检查点波次、检查点游戏时间，并提示“检查点之后的进度不会保存”。
- 第 0 检查点产生前，所有手动固定操作禁用并说明原因。
- 删除槽位解除槽位映射；只有没有其他槽位和活动会话引用时，才允许后续清理档案目录。

## 4. 捕获时机

### 4.1 第 0 检查点

教程结束并且正式日计划已经提交、正式世界已经建立后生成。读档启动不得再次生成第 0 检查点。

### 4.2 波次检查点

1. 接收 `combat_wave_cleared(wave_number)`。
2. 延迟到当前战斗清理调用栈结束；同一轮重叠波次信号合并。
3. 重新验证：非教程、敌人数为 0、无活动战役、未失败。
4. 设置短时恢复/捕获屏障，保留玩家原暂停状态。
5. 同一调用栈同步捕获全部权威系统，不等待网络或异步回调。
6. 校验跨系统引用与 Schema，编码当前视口缩略图，并分别以临时文件替换当前 `archive_id/auto` 的状态、图片和元数据。
7. 解除屏障并显示成功或明确失败。

第五波胜利时先冻结世界；只有结局状态成为 `llm` 或 `template_fallback` 后才发布最终自动检查点，避免读档后重复请求结局模型。

## 5. 权威字段

| 系统 | 保存 | 不保存 / 重建 |
|---|---|---|
| GameState / TimeSystem | 日时分秒、胜负、原因、结算快照 | 暂停来源、减速请求、表现步进 |
| ResourceSystem | 每种具体资源和物品的实际数量 | 容量等配置派生值 |
| BuildingSystem | HP、Max HP、等级、摧毁锁存、特殊状态；修复/升级已支付事务和剩余时间 | 工位占用、助手、场景节点 |
| CraftingSystem | 配方目标、revision、完成阶段、实际投入账本、待领取产物 | 工人小数进度、锁、Action 相位 |
| NPCSystem | 招募、属性、技能、成长、需求、钱/酒、昏迷/逃离、持久增益、命令、计划、装备、日记、知识 | 移动请求、工位预约、攻击相位、对话/LLM 活动 |
| NPCNeedsSystem | 饱食/疲劳及零饱食伤血的小数余数 | 战斗冲刺瞬态 |
| DailyPlanSystem | 已提交计划、计划版本、一次性节点执行键 | 当前 Action、重估/对话判定请求和异步队列 |
| MemorySystem | 完整事件表、全局/NPC/广场索引、事件计数器、公告与参考日程 | 地点运行缓存；由恢复后的世界重建 |
| DailyReflectionSystem | 已反思日期、已完成窗口、最后成功结束点 | 在途请求和进行中的反思窗口 |
| HorseSystem | 马匹实体、顺序、繁育累计/冷却、栏位和指派、序列号、RNG、待命名幼驹 | 运动路线、表现节点、反馈累计 |
| EquipmentSystem | 装备存放在 NPC 权威档案中 | 定义与 UI 投影从配置重建 |
| DefenseDeviceSystem | 存活部署、槽位、HP | 攻击目标、蓄力、冷却、弹体、废墟表现 |
| MerchantSystem | 马车阶段/位置、访问日、库存、路线模式、RNG | Navigation RID、路径节点和调试结果 |
| CombatSystem | 已触发/完成波次和一次性预警标记 | 敌人、弹体、近战提交、集结/避战和战斗动作 |
| PietySystem | 当前虔诚、累计产出、NPC 贡献 | 流星/燃烧/弹坑表现相位 |
| EpilogueSystem | 已落入 GameState 的最终 `llm` / `template_fallback` 结局 | 在途 request id |
| SpatialSaveSystem | NPC 语义地点 / 建筑、商队位置；波次检查点固定无敌人 | NPC 任意世界坐标、世界原点、NodePath、RID、导航路径、挂接和工位 |

## 6. 事务规则

### 6.1 回滚并重建

制造、修复、治疗、训练、对话、反思、寻路、攻击、弹体和 UI 确认的运行相位不保存。NPC 空间快照也不保存任意身体坐标：只保存当时已经提交的信息地点 / 建筑。加载时先按 NPC ID 把成员直接安置到 `data/npc_stay_positions.json` 为该地点配置的个人隐性停留点，避免多人共用建筑中心、门口或工位；再按保存计划重新派发符合条件的 NPC。缺失地点配置时回退本人初始安全点并报告 fallback；已逃离成员保持站外，不重新放回建筑。

既有 `formal_npc_spatial_checkpoint_v1` 继续可读，但其中旧 `position / world_origin` 只作为废弃兼容字段忽略；新检查点写 `formal_npc_spatial_checkpoint_v2`，不再产生这两个字段。该子结构升级不改变玩家存档的顶层 Schema v1。

`once_per_plan_hour` 的执行键只代表已提交完成的事实。若空间快照同时标记当前小时同一行动仍为 `in_flight_action.active=true / restore_policy=rollback`，加载时必须先删除这一项未完成派发键再重派；没有在途标记的已完成执行键必须保留，避免重复进食、饮酒或其他资源结算。该规则可直接修复既有 T0355 v1 存档，无需迁移状态文件。

正在进行但尚未形成事件的对话与所有 HTTP / LLM 请求直接取消，不伪造回复，也不自动补发。已经形成的对话事件、见闻、日记和知识照常保存。

### 6.2 已提交事务

- 修复/升级在开工时已经扣费，因此保存建筑级任务、目标、实际成本、总时长和剩余时长；助手在加载后重建。
- 制造阶段已经扣费，因此保存实际投入账本。更换目标退款读取该账本，不用新版配方反推旧成本。
- 待领取产物是已结算事实，必须保存。
- 待命名幼驹是已经成立的出生事务，必须保存；弹窗不保存，加载后重新发出命名请求。
- `once_per_plan_hour` 等一次性计划节点保存执行键，防止读档重复吃饭、饮酒、送礼、弥撒或对话。

## 7. 统一恢复顺序

1. 主菜单只读元数据，验证版本、状态文件和校验值。
2. 发布 `LOAD` 启动意图并创建干净 `Main`；禁止新游戏教程、开局计划和第 0 检查点。
3. 暂停时间并进入静默恢复屏障，重置跨场景 GameState。
4. 初始化当前版本静态配置与正式世界，并同步生产 NavigationMap。
5. 静默恢复 GameState 和 TimeSystem。
6. 恢复 BuildingSystem 结构，再恢复 ResourceSystem。
7. 恢复建筑修复/升级事务与 CraftingSystem 已提交项目。
8. 恢复 NPCSystem 核心、成长、需求、命令、计划、长期记忆。
9. 恢复 HorseSystem，再重建 EquipmentSystem 坐骑/装备投影。
10. 恢复 DefenseDeviceSystem、PietySystem。
11. 恢复 MemorySystem 事件与索引、公告，再恢复 DailyReflectionSystem 完成标记。
12. 恢复 CombatSystem 波次进度；波次检查点不生成敌人。
13. NavigationMap 就绪后，通过 SpatialSaveSystem 按 NPC 语义地点恢复个人停留点，并恢复逃离与商队空间状态。
14. 重建容量、建筑特殊状态、地点成员、马匹/器械表现和 UI 投影。
15. 清空 Action、Dialog、LLM、反思、战斗和 UI 瞬态。
16. 恢复 DailyPlanSystem 计划版本与一次性执行键，仅为可行动且处于工作模式的 NPC 执行当前计划一次。
17. 如有待命名幼驹，重新发出命名请求；如为结局档，直接展示已保存结局。
18. 解除屏障；非结局档回到正常可运行状态，玩家暂停来源与倍速不从存档恢复。

所有恢复入口必须支持静默模式。恢复本身不得新增事件、见闻、资源交易、伤害、经验或 API 请求。

## 8. 版本与平衡调整

存档保存运行事实，敌人波次、配方定义、建筑定义、NPC 静态人物设定等继续从当前版本配置读取。单纯调整难度数值不需要重做存档框架。

以下变化需要显式迁移：字段重命名、ID 删除或替换、权威归属变化、已提交事务算法变化。迁移逐版本执行，不允许把高版本存档猜测性降级读取。
