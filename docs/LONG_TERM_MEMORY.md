# LONG_TERM_MEMORY.md

> 记录长期稳定规则、踩坑、架构约束。  
> 这里的信息用于防止 Agent 反复犯同样错误。

## 稳定规则

- 不要把项目做成大规模 AI 小镇。
- 当前核心是“边境驿站压力锅”。
- 优先做最小可运行闭环。
- 不要让战斗系统压过 AI 征召与记忆系统。
- 不要让 LLM 直接控制权威数值。
- 不要把游戏设计塞进 Prompt。
- 不要在脚本中硬编码 NPC 档案。
- 时间变速只作为逻辑时间/数值结算倍率，不修改 Godot 全局速度，也不直接改变 NPC 移动或动画速度。
- 暂停是独立机制：空格只暂停/继续，不切换加速；暂停应停止逻辑时间、NPC 移动、战斗和资源/状态结算，但不冻结 UI、后端请求或 LLM 对话/判定等待。
- LLM 等待时使用 TimeSystem 慢速请求把有效逻辑倍率降到默认 `1/60`；请求结束、失败或超时必须释放。
- 事件系统是信息系统底座：每个事件必须关联 NPC、地点、可见性和结构化 payload，并通过 MemorySystem 统一写入。
- NPC 短期记忆由亲历事件库和见闻库组成，二者不能混成一个不可区分的文本列表。
- 主厅、围墙、城门不可进入；它们的状态进入广场信息空间，NPC 进入广场时继承这些状态。
- 文档必须跟着代码更新。

## 已知风险

- 系统体量容易膨胀。
- LLM 调用容易爆成本。
- NPC 自主计划容易不可控。
- Godot 场景结构如果不维护，会很快混乱。
- 记忆系统如果不压缩，会迅速撑爆上下文。
- 战斗如果做得太深，会拖慢核心 AI 玩法。

## 防错策略

- 每次只实现一个模块。
- 每个模块都先做最小版本。
- 新增文件必须更新 `MODULE_INDEX.md`。
- 新增设计必须更新对应模块文档。
- 任何大改前先阅读 `CURRENT_STATE.md`。
