# 正式驿站启动加载性能优化方案

任务：T0400
制定日期：2026-09-12
状态：已于 2026-09-13 完整回退，暂不实施

> 回退决定：用户实机确认烘焙路径导致多处场景与建模消失。该风险不可接受，因此删除烘焙产物、烘焙 / 验证工具、运行时烘焙恢复分支和主菜单后台预热，恢复原有程序生成正式驿站。以下内容仅保留为历史分析与候选方案，不代表当前运行架构；未经用户再次确认不得重新接入。

## 1. 问题与基线

正式启动链已经是 `MainMenu -> Main` 单次切换，不再存在旧版 `Main -> MainMenu -> Main` 双重加载。当前慢点发生在 `Main.tscn` 进入场景树后：`StationLayoutController._ready()` 读取四份配置，并在主线程同步生成地形、道路、环境、围墙、12 座建筑、工位、碰撞、空间锚点、AStar 网格和生产 NavigationMesh。

Godot 4.6.2 冷进程分段基线：

| 阶段 | 耗时 |
|---|---:|
| `load(Main.tscn)` | 2198.921 ms |
| `PackedScene.instantiate()` | 8.301 ms |
| `add_child` 至全部 `_ready()` 返回 | 10677.451 ms |
| 合计 | 12884.673 ms |

隐藏 Main、关闭教程仍得到同一量级；移除 `StationLayoutController` 的对照中，进树阶段降至 388.604 ms、总计 2548.376 ms。正式运行态约有 11,880 个生成 Mesh；`BuildingRoots` 约 11,271 个节点 / 8,688 个 Mesh，证明瓶颈是同步建图，不是 NPC 移动、教程、LLM 或时间推进。NavigationMesh 直接烘焙约 180 ms，只是次要组成。

教程完成后的固定 5 秒交接卡属于已确认设计等待，不计入加载优化；交接权威计算、教程隔离和第 1 日 06:00 基线不在本任务调整。

## 2. 不变合同

- `station_layout.json`、`physics_navigation.json`、`building_fixture_layouts.json`、`environment_art.json` 继续是设计源，生成场景不成为第二份玩法配置。
- 不调整建筑数量、位置、旋转、等级、HP、容量、工位、资源、战斗、NPC、波次、时间或 LLM 行为。
- 不改变可见网格、材质、阴影、屋顶淡出、门动画、升级 / 损伤 / 摧毁、脚手架与功能灯的表现规则。
- 不改变碰撞层、Shape、导航源、NavigationMap、NavigationLink、AStar 可行走规则或空间查询接口。
- UI 只呈现加载状态；不因优化提前推进 Main 世界、生成 NPC 计划或触发真实 provider 请求。

## 3. 候选目标架构（当前未启用）

开发期流程：

`四份配置 + 既有生成器 -> bake_formal_station_layout.gd -> FormalStationStaticCore.scn + 来源指纹`

玩家运行流程：

`Main -> 校验烘焙版本/配置指纹 -> 实例化已烘焙静态根 -> 重建轻量运行索引 -> 绑定动态系统`

`.scn` 只保存生成结果；JSON 与生成器仍是唯一维护入口。运行时 `StationLayoutController` 保留所有公开空间接口和动态绑定，只跳过已经离线完成的固定节点创建、材质构造、静态合批和 NavigationMesh 烘焙。AStar 内存对象与 NavigationMap RID 仍在运行时安全建立，因为它们不是可持久化场景状态。

## 4. 分阶段实施

### P1：高成本静态核心烘焙

- 烘焙 `BuildingRoots` 与 `WallsAndGates`，覆盖最大热点，同时保留控制脚本。
- 所有烘焙节点使用统一元数据门禁；其脚本在运行时只恢复节点引用、材质缓存、动态信号和组，不重复创建几何。
- `StationLayoutController` 从烘焙根重建 `_building_roots`、建筑名标签、战略血条等轻量索引，再按原路径建立空间锚点与运行时 NavigationMap。
- 场景携带 `bake_schema`、`generator_revision` 和四份配置 SHA-256；不匹配时开发运行回退程序生成并给出明确警告，正式导出验收不得依赖回退。

### P2：环境与寻路数据烘焙

- 在 P1 回归稳定后，将道路、正式环境表现和其确定性散布加入烘焙，避免一次改动同时触碰全部动态灯光与环境控制器。
- 预保存 NavigationMesh 资源；运行时只创建私有 NavigationMap RID、挂接 Region / Link 并恢复 AStar 数据。

### P3：主菜单线程预载与过渡

- 菜单首帧稳定后只做 `ResourceLoader.load_threaded_request(Main.tscn)`，不实例化 Main，不执行 `_ready()`，不推进世界或 LLM。
- 点击开始时显示保持既有封面视觉的加载层，停止封面 SubViewport 持续刷新，并在资源就绪后切入 Main。
- 线程预载只能隐藏资源 I/O；P1/P2 负责消除主线程建图，两者不能互相替代。

## 5. 验证与回滚

- 烘焙前后记录节点类别、建筑/工位/碰撞/导航数量与关键 NodePath；对差异逐项解释，禁止用放宽断言收口。
- 跑正式布局、生产导航、建筑表现、屋顶、升级 / 修复 / 损伤、门、教程和 Main 启动回归。
- 使用相同相机、昼夜、分辨率做实际渲染截图，检查构图、材质、阴影、门叶、屋顶和地面接触。
- 冷进程至少重复三次，分开报告资源读取、场景实例化、进树 `_ready()` 和首个可交互帧；不以编辑器热缓存样本冒充冷启动。
- 任一机制、碰撞、导航或可见表现不等时，保留旧程序生成回退，修复烘焙恢复逻辑后再启用正式产物。

## 6. 玩家影响

预期收益是显著缩短点击“开始游戏”后的冻结/黑屏时间并降低 CPU 与内存分配峰值。玩家不需要 Godot 编辑器，烘焙场景随 `.pck` 一起发布。代价是安装包与补丁可能略增、开发者修改地图后必须重新烘焙；指纹校验用于阻止旧产物误入正式包。文件格式本身不是主要收益，收益来自不再为每次开局执行同一批程序化构造。

当前仓库没有 `export_presets.cfg`，因此本轮无法生成特定平台安装包做最终 PCK 清单检查。新建导出预设时应使用“全部资源”，或将 `scenes/generated/*.scn` 加入 include filter；若使用“所选场景及依赖”且未显式包含该目录，运行时字符串加载的产物可能不进包并触发程序生成回退。

## 7. 2026-09-12 试做记录（已回退）

P1 已生成 `scenes/generated/FormalStationStaticCore.scn`（约 7.83 MiB），覆盖 `BuildingRoots` 和 `WallsAndGates`。产物携带 `formal_station_static_core_v1` schema、`t0400_p1_v2` 生成器版本和四份设计源 SHA-256。运行时校验不通过会明确警告并回退旧程序生成路径，不会用错位地图继续运行。

烘焙器会移除血条、空马匹表现、空脚手架、运行时功能灯和空间索引，这些仍由权威状态在载入后恢复。已合批的静态结果保留，对应的 1,747 个隐藏源网格从产物中剔除；地表接触遮罩依赖的真实地基例外保留。烘焙产物为 11,026 个节点 / 8,566 个 Mesh。

P3 已在主菜单稳定后后台请求 `Main.tscn` 和静态核心。菜单阶段只解析资源，不实例化 `Main`；点击后按钮立即显示“载入中…”并停止 3D 封面的持续刷新，资源完成后从缓存 `PackedScene` 切入。开发工具若在预载进行中另行实例化 Main，运行端会先 join 同一请求，避免并发解析共享 Mesh。

同机 headless 对照（单次冷进程，因 OS / Godot 缓存存在波动，保留原始数值）：

| 路径 | 资源加载 | 实例化 | 进树 / `_ready()` | 合计 |
|---|---:|---:|---:|---:|
| 强制旧程序生成 | 3350.022 ms | 16.607 ms | 9520.953 ms | 12887.582 ms |
| 烘焙静态核心 | 3270.398 ms | 16.080 ms | 6836.867 ms | 10123.345 ms |
| 菜单后台预热后点击 | 菜单期完成（10562 ms） | 并入切场景 | 8081 ms 至 Main ready | 8081 ms 玩家点击等待 |

相对本轮同机旧路径，直接 Main 总时间减少约 21.4%，在菜单停留足以完成预热时，点击后等待减少约 37.3%。自动化和 Godot MCP 实机确认使用 baked 路径，12 座建筑、109 个设施、61 个工位、31,715 个 AStar 可行走格、生产 NavigationMesh、门 / 屋顶 / 阴影批次保持可用；地表接触专项为 14 个建筑基座、14 段墙基、12 条入口，无新增合同失败。

P2 暂不与本轮强行合并：环境分支还包含昼夜、地表接触和功能灯动态控制器，需单独做生命周期与截图对照。该部分作为后续性能任务，不改变当前正式包已获得的 P1/P3 收益。

回归记录：生产导航、屋顶可见性、15 建筑脚手架生命周期、地表接触、功能灯和 T0354 前端门禁通过。旧 `verify_t0131_p1d_building_auto_doors.gd` 仍报“铁匠铺开放正面存在隐形墙碰撞”；强制程序生成与烘焙路径同样复现，判定为本任务前的独立基线缺陷，本轮未改动该碰撞合同。

## 8. 2026-09-13 回退记录

用户实机发现多个场景与建模在烘焙路径中消失，说明节点剥离与运行时恢复未覆盖完整表现生命周期。现已撤销 P1 / P3 的全部程序接线并删除生成产物与专项工具，正式运行重新逐项执行原生成器；菜单恢复直接 `change_scene_to_file(Main.tscn)`。本方案不再作为当前性能收益，不继续 P2，也不以扩大剥离名单或放宽视觉断言修补。若未来重启，只允许先做不删除源节点的只读分段剖析和逐建筑截图金样对照，再由用户确认是否进入实现。
