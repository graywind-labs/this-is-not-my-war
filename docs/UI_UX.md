# UI_UX.md

## 主界面

俯视 3D 驿站地图。

当前实现（T0104 / T0202 / T0204 / T0205 / T0303 / T0004 / T0604 / T0701 / T0702 / T0703 / T0704 / T0705 / T0011 / T0012 / T0014 / T0015 / T0016 / T0904 / T1105）：

- `Main/UI` 使用 `CanvasLayer`。
- `Main/UI` 绑定 `res://scripts/ui/UIInputFocusManager.gd`；当前任意 `LineEdit` / `TextEdit` 输入框获得焦点后，点击输入框外任意位置都会释放焦点，后续新增文本输入框默认遵循同一规则。
- `Main/UI/HUD` 使用 `res://scripts/ui/HUD.gd`，在左上角显示基础信息，避免遮挡主要驿站视角。
- `HUD.gd` 会把 HUD 根节点设为鼠标忽略，避免全屏 HUD 背板拦截 3D 建筑点击；具体按钮仍保留自身交互能力。
- `Main/UI/HUD/TitleLabel` 显示游戏标题。
- `Main/UI/HUD/DayLabel`、`TimeLabel`、`PhaseLabel` 显示当前天数、`HH:MM:SS` 时间和阶段；当前随 `TimeSystem` 推进并监听 `EventBus.time_changed` / `hour_started` / `day_started` 刷新。
- `Main/UI/HUD/ResourceStrip` 由 `HUD.gd` 按 `ResourceSystem.get_resource_ids()` 动态生成资源标签，主栏显示 `data/resource_defs.json` 中按 `ui_order` 排列的非聚合资源：第纳尔、粮食、餐食、酒、木材、石料和铁。
- `HUD.gd` 监听 `EventBus.resource_changed`，资源变化后自动刷新资源栏；武器、盔甲、马匹整备和工程器械等聚合库存不在主栏重复显示。资源栏右侧提供“装备”和“器械”按钮，打开 `ResourceDetailPanel` 查看装备聚合库存、可分配装备定义、已分配装备数量，以及工程器械库存说明。详情面板会出现在各自按钮左下方，并夹在可用屏幕范围内；该详情面板只读取 `ResourceSystem` / `EquipmentSystem` / `NPCSystem`，不修改资源或装备权威状态。
- `Main/UI/HUD/SpeedButton` 已接入 `TimeSystem`，点击后按 `x1` / `x2` / `x4` 循环切换流速。
- `Main/UI/HUD/PauseButton` 控制暂停/继续，空格键绑定到同一套暂停/继续逻辑；空格不触发速度切换。
- `AlarmButton` 已接入警铃集结：点击后调用 `CombatSystem.trigger_combat_alarm("hud")`，让所有 NPC 记录警铃事件，并让入伍且有主武器的可行动 NPC 前往城门外防线集结。
- `Main/UI/HUD/BackendStatusLabel` 显示 LLMBridge 的后端 health check 状态；初始为未检查，调用 `LLMBridge.check_health()` 后显示已连接或未连接。
- GM 调试面板已可显示 TimeSystem 有效逻辑倍率、LLM 慢速请求、时间上限请求和敌人快照中的战斗策略状态；当前 HUD 速度按钮仍只显示玩家设定的速度倍率，不显示敌人在场 cap 后的实际倍率。
- `Main/UI/BuildingPanel` 绑定 `res://scripts/ui/BuildingPanel.gd`，点击建筑后显示建筑名称、等级、HP / Max HP、按类型分组的工位 / 床位 / 训练位空闲数与占用者、地点信息占位；修复/升级消耗与条件不常驻显示在面板正文中。
- `BuildingPanel` 内的修复、升级按钮会调用 `BuildingSystem`；按钮根据当前 HP、等级、配置、是否已有修复/升级作业和资源是否足够自动启用或禁用。建筑受损、正在修复或正在升级时不能开始升级，正在升级时也不能开始修复。光标悬停在修复/升级按钮上时，按钮旁边显示操作所需资源和条件提示框。修复或升级进行中会显示进度、剩余时间、速度倍率和协助人数；进度刷新通过 `building_state_changed` 更新当前可见建筑面板，不触发新的建筑点击选择。
- `Main/UI/NPCPanel` 绑定 `res://scripts/ui/NPCPanel.gd`，点击 NPC 后显示 NPC 基础状态、力量/智力属性、专长、当前装备、事件库、见闻库和日记；面板可见时，当前 NPC 状态变化会随 `npc_state_changed` 刷新，记忆变化会随 `npc_memory_changed` 刷新。T1005 后，名字旁会显示 LLM 状态：“正在思考”“正在计划下一步行动”或“正在熟睡”。
- `NPCPanel` 固定在右上角，面板内容增多时只向下延展；事件库、见闻库和日记各自显示在固定高度滚动框内，刷新后自动滚到底部，用户仍可手动向上查看旧事件或旧日记，不会把 NPC 面板无限拉长。点击事件库或见闻库区域会打开居中的详情弹窗，展示当前 NPC 对应记录的完整字段；点击弹窗右上角 `×` 可关闭。
- `NPCPanel` 和 `BuildingPanel` 会随 `npc_clicked` / `building_clicked` 互斥切换，右上角只显示当前点击对象的面板；建筑修复、受损或升级等状态刷新不会抢占玩家刚切到的 NPC 面板，工作中 NPC 的持续状态刷新也不会重新打开已经切走或隐藏的 NPC 面板。
- `Main/UI/DialogPanel` 已接入 `res://scripts/ui/DialogPanel.gd`：显示 NPC 名字、公开性、应征 toggle、当前轮次、历史对话、自由文本输入、发送按钮、攻击按钮和结束按钮；它与 `OrderPanel` 互斥，但不与右上角 `NPCPanel` 互斥。
- T0705 后 NPC 主动交涉时会在头顶显示 `?` 气泡；玩家点击该 NPC 会优先打开对话面板并显示 NPC 预先确定的第一句话，不先打开 NPC 面板。T1005 后，NPC 等待可取消的对话 / 闲聊 / 每日计划 / 计划修订 LLM 时，头顶显示 `...` 标记；首次睡眠总结期间显示禁止标记。
- `Main/UI/GMPanel` 绑定 `res://scripts/ui/GMPanel.gd`，开发模式下显示半透明可拖动 `GM` 按钮；点击后在 GM 按钮附近打开 GM 调试面板，拖动按钮时已打开的面板会跟随重定位并夹在可用屏幕范围内。面板提供命令输入框、执行结果区，以及资源、时间倍率快照、建筑、NPC、行动、后端 / LLMBridge、记忆/见闻/广场公告、首次睡眠总结、长期记忆和 LLM 状态等调试入口。
- GM 面板顶部 `GM_ENABLED` 常量可用于开发/上线显示切换；GM 只调用现有系统接口或 `debug_*` 接口，不承担资源、HP、事件、行动或时间倍率的权威结算。T0014 后普通行动统一通过行动下拉和“指定行动”按钮触发，工作、吃饭、睡觉、训练场教官和受训者等普通行动不再额外提供并列快捷按钮；协助修复、协助升级、协助治疗等需要额外目标参数的入口保留。T0904 后 GM 可通过按钮或 `assign_attribute <npc_id> <strength|intelligence>` 命令调用 NPCSystem 分配技能点。T0015 后 GM 的 NPC 分组提供“设为入伍”按钮和 `recruit_npc <npc_id>` 命令，调用 NPCSystem 入伍权威入口。T1103B/T1103C 后 GM 战斗分组提供“警铃集结”“行为模式快照”“模拟避战”“推进集结等待”按钮和 `alarm` / `rally` / `behavior_modes` / `avoid_npc <npc_id>` / `advance_rally_wait [game_seconds]` 命令；“模拟避战”适用于未入伍或已入伍但无主武器的非战斗人员。T1104A 后，GM 时间快照和敌人快照可观察 `combat_enemy_presence` 时间上限请求，验证敌人在场时有效倍率不超过 `x1`；T1104B 后，“推进敌人AI”按钮的 60 游戏秒步长约等于 1 秒战斗动作，可用于观察攻速基准。

## NPC 面板

点击 NPC 显示：

- 姓名
- HP；经验以 `经验：当前 / 阈值` 显示在 HP 右侧
- 属性：力量、智力；只有有未分配技能点时，属性数值旁显示 `+1` 按钮
- 专长，由最高熟练度推导
- 当前行动
- 当前行为模式：工作 / 集结 / 战斗 / 避战 / 昏迷 / 逃离
- 饱食、疲劳、士气
- 是否昏迷
- 职业熟练度与武器熟练度
- 当前装备
- 当前记忆摘要，后续应区分亲历事件库和见闻库
- 对玩家态度
- 对话按钮
- 赠予金钱按钮
- 给予/更换装备按钮
- 战斗策略下拉框，若已入伍且有主武器
- 指令按钮，若已入伍

当前实现（T0303 / T0405 / T0703 / T0704 / T0014 / T0015 / T0904 / T1004 / T1105）：

- 点击 NPC 会打开右上角 `NPCPanel`。
- 当前按姓名、HP / Max HP 与经验、属性、专长、饱食度、疲劳度、金钱、当前装备、是否昏迷、是否已入伍、当前行动占位、职业熟练度、武器熟练度、事件库、见闻库和长期日记显示。
- 面板以顶部为固定基准，内容增多时向下延展，不再向上下两边同时增长。
- 属性显示力量和智力，对应 `game_design.md` 中体力相关产出/生命/移动/载重，以及智力相关产出/熟练度成长系数。
- T0015 后面板不再显示独立“成长”说明文本；经验以 `经验：当前 / 阈值` 显示在 HP 行右侧。力量和智力在同一属性行内显示；只有存在未分配技能点且对应属性未达上限时，才在该属性旁显示 `+1` 按钮。按钮只调用 `NPCSystem.assign_npc_attribute_point(...)`；没有未分配技能点时按钮消失。AI 不会自动分配这些技能点。
- 专长不是写死职业，而是从 NPC 最高的固定熟练度维度推导。
- 面板可通过关闭按钮隐藏。
- T1103B/T1103C 后 NPC 面板会显示当前行为模式；T1105 后会明确区分非战斗人员同级“避战模式”和已入伍持武器 NPC 在战斗模式中的“避战策略”。
- `NPCSystem.update_npc_state(...)` 修改状态后会发出 `npc_state_changed`，打开中的 NPC 面板会刷新；如果 NPC 面板已经因点击建筑或关闭按钮隐藏，状态刷新不会重新打开它。
- `MemorySystem` 写入 NPC 事件库或见闻库后会发出 `npc_memory_changed`，打开中的 NPC 面板会刷新对应滚动框并自动滚到底部；若对应详情弹窗正打开，也会同步刷新弹窗内容。T1004/T1005 后，首次睡眠总结写入长期日记时会通过 `npc_state_changed` 刷新当前 NPC 面板，日记同样显示在固定高度滚动框内。
- 当前已实现对话按钮；已入伍 NPC 会显示可用“指令”按钮并打开独立自然语言指令面板，未入伍 NPC 不显示该按钮。点击“对话”或“指令”不会关闭 NPC 面板。
- 面板已实现非对话交互区：可选择“同地点公开”或“私下”；“给钱”按钮旁的数字输入框用于调整赠予金额，该输入框只保留数字，WASD 等字母键不会写入金额，点击输入框外任意位置会退出输入状态；“装备武器”旁可选择剑盾、长杆、弓、弩等主武器，按钮会调用 `EquipmentSystem`，为已入伍 NPC 消耗 1 个全局 `weapons` 库存并写入装备事件；同一行的战斗策略下拉框读取 `CombatSystem.get_npc_combat_strategy_options(...)`，只在已入伍且有主武器、存在可用策略时启用，选择后调用 `CombatSystem.set_npc_combat_strategy(...)`。当前装备文本会显示由 `EquipmentSystem` 按主武器和 `equipment.mount` 槽返回的战斗定位。T1006 起，攻击按钮移入对话窗，NPC 面板不再提供直接攻击入口。NPC 面板不提供“要求休息/请求治疗”按钮，这类意图由已入伍 NPC 的自然语言指令承担。UI 只触发系统入口，不自行结算事件、HP、库存、装备、兵种结果或战斗策略行为。

## 指令撰写与发布面板

只有已入伍 NPC 可以从 NPC 面板打开指令面板。该面板不显示工作、吃饭、睡觉、训练等行动选项列表，而是提供自由文本输入：

- 打开时显示该 NPC 当前 `current_order.text`；已有内容可直接修改。
- 点击“发布”时，只有新文本与原指令不同才覆盖旧指令。
- 指令变化后写入目标 NPC 的 `private` `order_assigned` 事件，并立即触发统一计划重评估入口。
- 发布相同文本不写事件、不触发计划重评估。
- 点击“关闭”不保存任何编辑，无事发生。
- UI 只提交文本和显示状态；它不直接启动行动、修改计划结果或决定 NPC 是否服从。

后续 GM/调试信息需要能查看某 NPC 当前指令、最近修订号和发布后是否发起计划重评估，以验证无法仅凭前端文本确认的 Prompt 注入与重评估链路。

当前实现（T0703）：

- `Main/UI/OrderPanel` 绑定 `res://scripts/ui/OrderPanel.gd`，提供多行自由文本、当前修订信息、发布和关闭按钮。
- 发布由 `NPCSystem.publish_npc_order(...)` 权威处理；面板只提交文本并显示结果。
- 打开指令面板会关闭当前对话；打开对话面板会关闭当前指令面板，二者不会在中央重叠。
- GM 已可查看/发布当前指令和最近计划重评估请求；Prompt 注入与真实重评估结果仍由 T0703A/T1002 实现。

## 建筑面板

点击建筑显示：

- 建筑名称
- 等级
- HP
- 工位 / 床位 / 训练位占用状态；按类型显示 `空闲数/总数：占用者`
- 当前地点信息占位
- 修复按钮，资源足够、建筑受损且没有正在修复/升级时可用；修复开始后显示倒计时状态
- 升级按钮，资源足够、建筑完好、没有正在修复/升级且未达最高等级时可用；升级开始后显示倒计时状态

当前实现（T0204 / T0205 / T0016）：

- 点击 `BuildingSystem` 绑定过的低模建筑后，`EventBus.building_clicked` 会驱动 `BuildingPanel` 显示对应建筑信息。
- 建筑 HP、修复/升级进度、协助人数、等级等状态变化通过 `EventBus.building_state_changed` 刷新当前可见的对应建筑面板；如果玩家已经点击 NPC 切到 `NPCPanel`，该刷新不会重新显示建筑面板。
- 面板位于屏幕右上角，可通过关闭按钮隐藏。
- 2026-05-20 已修正真实鼠标点击无法打开面板的问题：HUD 根节点不再吃掉地图点击，`BuildingSystem` 也会在 `_unhandled_input` 中用相机射线拾取建筑点击区。
- T0016 后，建筑面板不再显示单独的“当前工作位 x/x”汇总行；工位信息合并到具体类型行，例如 `厨师 1/1：空闲`、`医生 0/1：莉娜`、`病床 1/2：马塞尔`。第一个数字是该类型当前空闲位置数，第二个数字是该类型真实总位置数；占用者显示 NPC 名字，多个占用者用顿号分隔。
- 修复/升级按钮可触发倒计时修复和倒计时升级；资源不足、条件不满足或已有修复/升级作业时按钮禁用。修复/升级消耗和可执行条件只在按钮悬停提示框中显示，不写入面板正文。
- 当前不显示真实产出、储存或完整升级树。

后续需要补充：

- 当前产出
- 储存或消耗
- 升级条件
- 当前地点信息

地点信息后续应来自地点/建筑信息节点的当前状态，而不是 UI 自行拼接。建筑面板需要显示当前人员、工位/床位占用和建筑状态；普通建筑不显示公告牌状态。当前公告属于广场状态，应在广场面板、公告输入界面或调试信息中显示；面向单个 NPC 的当前指令不属于广场或建筑状态。不要显示“建筑保存的近期公开事件”，因为建筑不保存事件历史。广场面板或调试信息需要额外显示主厅、围墙、城门等不可进入实体状态。

## 操作提示原则

资源消耗、前置条件、禁用原因和类似“执行前确认”的信息，默认不常驻堆在信息面板正文里；面板正文优先显示对象的当前状态。按钮、图标或具体操作入口需要在悬停时于入口旁显示提示框，说明该操作的资源消耗和条件。提示框必须保持在屏幕内，靠近屏幕边缘时应翻到按钮内侧或夹在可视区域中。建筑修复/升级是该规则的当前实现样例。

## 对话界面

对话界面突出：

- NPC 名字
- NPC 表情或情绪
- 历史对话
- 玩家输入框
- 发送按钮

可选按钮：

- 提出应征
- 赠予金钱
- 结束对话

核心输入应支持自由文本，以突出 AI 玩法。

当前实现（T0701 / T0702 / T1006）：

- NPC 面板“对话”按钮打开中央对话窗口，NPC 面板保持可见；若当前指令面板已打开，会先关闭指令面板。仅打开或关闭对话窗不会打断 NPC 行动、取消 NPC LLM 请求、写入事件或触发计划重评估。
- 玩家输入文本并点击发送后，才通过 `DialogSystem -> LLMBridge -> /npc/dialogue` 获取 Mock 回复；此时才取消目标 NPC 的可取消 LLM 请求并打断普通日常行动。历史区显示守备官与 NPC 的发言。
- 玩家-NPC 对话显示“不限轮次”；NPC-NPC 对话默认最多 5 轮，双方各发言一次后轮次加一。
- “同地点公开”可在首轮发送前切换；首轮发送后锁定，避免同一场对话中途改变传播规则。
- 当目标 NPC 处于集结、战斗或避战模式时，“同地点公开”默认开启且不可关闭；UI 应以禁用态显示这是战时公开对话，不允许切换成私下对话。
- “提出应征”现在是右上角、位于“同地点公开”下方的 toggle，会标记下一次玩家消息；发送后自动清除标记。后端返回接受时 NPC 面板立即显示已入伍，拒绝时状态不变。已入伍 NPC 的“提出应征”toggle 禁用。
- 等待 NPC 回复期间，输入框仍可编辑，发送和攻击按钮禁用；玩家点击结束会取消本次异步对话 LLM，请求结果返回后不再应用。若未完成 NPC 回复，本轮不写 `dialogue_turn`，也不触发对话重评估。
- 攻击按钮位于发送按钮旁。点击后先造成 10 点伤害并写入惩戒攻击事件，再请求 NPC 对“守备官攻击了你以示惩戒”作出回复；若攻击回复未返回就结束对话，攻击事件不撤销，未完成回复不入库，结束时仍触发一次计划重评估。
- 结束对话按钮关闭窗口；只有本次已完成玩家消息与 NPC LLM 回复，或已提交攻击事实，才会触发计划重评估。只打开查看历史后关闭无事发生。
- 如果 NPC 在对话过程中因警铃、接敌、避战、低血量自身心理判定或敌人攻击触发更高优先级模式切换，DialogSystem 必须强制关闭对话框、取消未完成 LLM 请求并让模式切换优先生效；未完成回复不写入 `dialogue_turn`。
- 集结 / 战斗模式下与已入伍且有主武器 NPC 对话，回复结构会包含 `wartime_reaction`：`none`、`escape` 或 `morale_boost`。避战模式下与非战斗人员对话仍可使用“提出应征”；若接受但仍无主武器，程序会保持避战，只有装备主武器且场上仍有敌军时才切换进入战斗模式。

## 主动交涉气泡

当 NPC 计划中选择主动找玩家交涉时：

- NPC 头顶出现问号气泡。
- 玩家点击后打开对话界面；该点击不会先弹出 NPC 状态面板。
- 对话界面使用既有 `DialogPanel`，历史区先显示 NPC 预先确定的开场问题。
- 玩家回复后进入正常玩家-NPC 对话逻辑。
- 对话结束后 NPC 重新评估计划。
- 若 1 游戏小时内无人点击，问号气泡自动消失。

当前实现（T0705）：

- 问号气泡由 `NPC.gd` 运行时创建为 `ProactiveTalkBubble`，主动交涉有效时显示。
- 触发入口当前主要是 GM 面板“主动交涉”按钮或 `start_proactive <npc_id> <text>` 命令；正式计划系统生成主动意图仍归后续计划任务。

## 战斗信息

战斗时需要显示：

- 当前波次
- 敌人数量概览
- 我方参战人数概览
- 关键战场公开事件
- 昏迷 NPC 提示
- 建筑受损提示

战斗信息中的公开事件应来自广场即时广播与 NPC 已接收见闻。UI 只展示事件摘要，不决定事件是否公开，也不让后来进入广场的 NPC 自动获得过去事件。
