## T0094 对话记录入口与宿舍床位文案

- NPC 面板把原“对话”入口改为同一行的主按钮“对话”与右侧小按钮“记录”。“对话”继续承担新建 / 恢复会话及橙点提示；“记录”只读打开现有详情弹窗，不打断 NPC、不创建会话、不触发模型或计划修改。
- “对话记录”只显示当前 NPC 与守备官已经完成并落入全局事件档案的会话，包含普通守备官对话与逃离挽留，不混入 NPC-NPC 对话。每场保留完整说话者与正文，按第 N 天、历史波次阶段和事件时间分组；首次打开定位到最新记录，打开期间刷新继续沿用详情弹窗的滚动保持规则。
- 宿舍仍保留 8 人固定床与 2 张未分配床的程序事实，但建筑面板不向玩家标注“XX 专属”。十行与其他建筑位置使用同一文案：空床显示 `床位X：空闲`，有人使用时显示 `床位X：XX占用中`。UI 不分配、交换或清除床位归属。
- 两项功能都可直接在 `Main.tscn` 验证，不新增 GM 控件或第二套历史 / 床位事实源。

## T0088 平缓时间显示与入伍姓名颜色

- HUD 时钟在没有 LLM 慢速请求时显示 `HH:MM:00`，玩家选择 `x1 / x2 / x4` 或战斗将有效倍率限制到 `x1` 都不显示快速跳动的秒；LLM 请求慢速期间显示真实游戏秒，进入和退出慢速时立即刷新。
- 持续剩余时间采用同一策略。当前 HUD 波次倒计时与建筑修复 / 升级剩余时间在正常速度下向上取整到分钟并显示 `00秒`，慢速期间显示精确游戏秒。马匹繁育冷却原本就只显示天 / 小时 / 分钟，保持不变；GM 精确推进日志不属于玩家节奏显示。
- 建筑面板修复 / 升级正文和按钮使用 `x小时x分xx秒`，不再显示裸秒数。
- 入伍 NPC 的主场景姓名与 NPC 面板姓名使用淡绿色 `Color(0.64, 0.92, 0.68, 1)`；未入伍维持白色。世界姓名与 `HP / 当前行动` 拆为独立 Label3D，状态文字不随姓名变绿。

## T0086 HUD 倍速快捷键

- 主键盘数字行 `1 / 2 / 3` 分别直接设置玩家选择倍率为 `x1 / x2 / x4`；按物理键位识别，不响应 `KEY_KP_1 / KEY_KP_2 / KEY_KP_3` 小键盘数字。
- `LineEdit` 或 `TextEdit` 获得焦点时不处理倍速数字，带 Ctrl / Alt / Meta / Shift 的组合也不抢占。空格继续只控制暂停 / 继续。
- 速度按钮点击仍按 `x1 -> x2 -> x4` 循环，tooltip 同时提示点击与数字键两种操作；按钮文本继续显示玩家选择倍率，敌人在场 cap 或 LLM 慢速的有效倍率仍从调试快照查看。

## T0083 应征结果行与精简事件标题

- 某次应征消息收到接受结果时，在该 NPC 回复正下方显示绿色 `✓ XX接受了守备官的应征请求`；拒绝时显示红色 `× XX拒绝了守备官的应征请求`。

## T0079 当前计划连续时段显示

- NPC“当前计划”详情把小时连续且行动、来源、目标、优先级、对话目的和可见说明一致的相邻项合并为一个时间段，例如 `13:00–16:00  酿造酒｜真实 LLM 日计划`。

## T0078 NPC 主动交涉取消状态

共享 `DialogPanel` 根据会话发起者区分取消语义：

- NPC 按计划主动找守备官：取消按钮半透明不可点击，悬停提示“驿站成员主动交涉不可取消对话。”；仍可选择完成或挂起。
- 守备官主动找 NPC：取消按钮保持可用，取消后视同本轮未发生。
- 已攻击会话继续不可取消；若同时属于 NPC 主动交涉，优先显示主动交涉提示。

按钮只是表现层，直接调用 DialogSystem 取消入口同样会被拒绝。主动交涉挂起到期按完成保存并重估，不弹出第二套界面；功能可直接在 `Main.tscn` 通过问号气泡和共享会话面板验证。

## T0053 跨小时等待反馈边界

本任务不新增玩家按钮或弹窗。目标仍在制定计划时沿用 T0052 的不可点击“NPC正在思考”；发起者的 NPC-NPC 对话等待不显示成已经开始的会话。若跨小时后发起者当前计划已不再与原目标对话，旧 pending / 气泡 / 双方预约直接清理，最近行动结果记录结构化失败并进入计划判别，不向玩家显示一场从未开始的对话。

## T0052 计划中 NPC 的对话反馈

NPC 面板从 NPC 运行态读取 `llm_activity`。当 `active=true && kind=plan` 时，“对话”按钮使用 Godot 原生 disabled 样式半透明禁用，悬停文本固定为“NPC正在思考”；该状态覆盖普通“打开对话面板”提示，但不覆盖已经存在的挂起守备官会话恢复入口。`npc_state_changed` 触发面板刷新，计划请求成功、失败或取消并清除活动后按钮自动恢复。即使 UI 状态在同一帧发生竞态，DialogSystem 仍以 `npc_planning` 权威拒绝，不依赖按钮保证数据正确。

## T0051 可拖动弹窗与守备官会话控件

`DialogPanel`、`NPCPanel`、`BuildingPanel`、`OrderPanel`、`NoticeBoardPanel`、`MerchantPanel`、NPC 记忆 / 背景详情和 HUD 具体库存详情统一把顶部标题栏作为拖动把手。拖动会解除原居中 / 右侧锚点，保留用户位置，并在拖动结束、重新显示和视口尺寸变化后把整个窗口限制在可用视口内。标题栏内部按钮仍优先处理自己的点击；GM 面板保留原有 GM 按钮拖动合同，原生确认窗口继续使用系统标题栏。

守备官对话底部由单一结束按钮改为等宽的“完成对话 / 取消对话 / 挂起对话”：完成保存当前会话，取消丢弃普通未锁定会话，挂起只隐藏窗口。攻击、NPC 主动交涉或已发送应征消息后，“取消对话”使用 Godot disabled 样式呈半透明并显示对应不可取消提示。玩家消息点击发送后立即进入历史，等待状态文案改为“守备官消息已发送，正在等待回复”，输入框仍可编辑草稿而发送 / 攻击禁用。

挂起 NPC 的头顶使用橙色 `↩` 会话气泡，区别于 NPC-NPC 的浅色 `...` 旁听气泡；点击气泡恢复同一会话。NPC 面板“对话”按钮左上角显示橙色圆点，按钮保持可点且提示“恢复挂起的对话”。

## T0049 对话计划自主判别与详情默认位置

- 守备官-NPC 对话面板不再显示“结束后重估计划”开关。玩家只决定是否对话、说什么、是否公开与是否提出应征；对话结束后是否修改计划、修改哪些阶段由 NPC 的 LLM 判别层决定。
- 有效对话结束后不在 UI 中假装已经重排计划。系统先判别 `revision_hours`：空集合保持原计划并在满足条件时恢复被打断行动，非空集合才显示后续“正在重新制定计划”状态并修订精确小时。对话窗内已提交的攻击也是有效本轮内容，即使没有完成 NPC 回复也进入同一判别；非对话触发才直接使用其受限小时范围。
- 事件库和见闻库详情每次从关闭状态首次打开时，默认滚到最底部，立即展示最近记录；若弹窗已经打开，因新记录而刷新时保留玩家当前阅读位置，避免阅读旧记录时被强制拉走。

## T0047 建筑面板透明测量输入边界

- BuildingPanel 首次打开或切换建筑时可以保持在布局树中透明测量，但透明阶段整棵 Control 子树必须禁用鼠标；修复、升级及建筑专属子按钮都不能拦截玩家投向 3D 世界的点击。
- 布局测量不得无限等待容器信号。当前每个测量阶段最多执行 4 次逐帧采样，并以 fit generation 丢弃过期任务；完成后必须恢复 `alpha=1`、有效自然高度和面板交互。修复 / 升级回调还会复验面板可见、非透明且不在测量中。
- 真实点击回归使用 Camera3D 把 15 个建筑定义的可见点击区投影到屏幕，并向 Viewport 发送鼠标移动、按下和释放；只选中建筑不得改变 HP、等级、资源或创建修复 / 升级作业。

## T0046 日记 / 知识与公告牌界面

- 日记详情只显示逐日第一人称日记，不再显示独立“记忆摘要”。知识详情仍按主体 / 关系组织，玩家可见的主体、关系和值一律为中文；未知技术键或值显示中文保底，不暴露蛇形英文或英文状态值。T0061 起玩家详情不再显示 `confidence` 和记录时间，这两个字段只保留在底层与调试输出中。
- `NoticeBoardPanel` 为“通告 / 日程表”双 Tab。通告页编辑已发布文本；日程表逐条编辑开始时间、结束时间与内容，支持新建和删除。两页均使用本地草稿；退出 / 关闭丢弃，只有发布才保存。日程表常驻显示世界内的非强制建议备注，不伪装成 NPC 个人计划；现有安排覆盖全天时仍会新建草稿行，并明确提示先调整或删除重叠时段再发布。T0066 后不再常驻显示草稿机制说明。

## T0045 建筑进度面板与镜头输入边界

- BuildingPanel 按建筑 ID 缓存上一次排版后的自然高度。修复 / 升级信号刷新时先保持该稳定高度，容器 `sort_children` 完成后再精确收缩或增高，不使用尚未更新的满滚动内容高度。首次打开 / 切换建筑在透明状态下完成排版后再显示，不让玩家看到测量中的空面板。
- CameraRig 仅消费本窗口收到的 WASD 按下 / 释放事件。按键释放、窗口失焦或 LineEdit / TextEdit 获得焦点时必须停止键盘平移；窗口失焦同时取消中键拖拽。

## T0044 对象面板信息与悬停反馈

- 马厩面板不再重复显示“马厩马匹”标题；摘要写为“在厩：…｜离厩：…”，逐匹马只显示“分配：某人 / 无”，不再追加与分配状态重复的骑手字段。
- NPC 未入伍时，因征召前置而禁用的武器、盔甲、马匹和战斗策略控件统一在悬停时提示“需先说服该人物应征入伍，才能进行这项操作。”；入伍后恢复控件自身用途或其他真实前置条件说明。
- 事件库 / 见闻库大号详情与小框遵循同一玩家信息白名单，只显示发生时间和 `summary`。详情首次打开定位到最底部的最新记录，打开期间刷新保留当前位置。内部事件类型、地点 ID、可见性、重要度、事件 ID、参与者 / 目标 ID 和 `payload` 继续保留给程序、存档及调试，不进入玩家详情。
- NPCPanel 与 BuildingPanel 的响应式高度调整不得先把面板临时撑到屏幕最大高度；浮动的建筑操作提示挂在 UI 画布而不是 BuildingPanel 内容树中，避免状态刷新或鼠标进出时在面板下方出现闪烁黑框。修复 / 升级提示仍显示在按钮附近并保持屏幕内。

## T0043A 服务依赖的可见反馈

建筑面板不新增“主动 / 被动工位”分类，也不要求玩家选择位置编号。小教堂仍逐行显示祭坛与 10 个祈祷席；祈祷席占用者的当前行动可区分普通祈祷和参加弥撒。诊所与训练场继续逐行显示诊疗位 / 病床、教官位 / 训练位的真实占用。服务者离岗后，承载者会被程序释放位置并在 NPC 当前结果 / 事件中显示失败，而不会留在位置上显示为零效率挂起。

GM 面板既有通用行动下拉自动读取 ActionSystem，因此新增 `attend_mass` 后无需增加专用按钮；可先给神父执行 `lead_mass`，再给其他 NPC 执行 `attend_mass`，并用中断主持验证参与者失败及祈祷席释放。

## T0043 建筑位置逐项显示合同

BuildingPanel 按 `building.workstations` 配置顺序逐项显示位置，服务人员所在位置在前、承载人员的位置在后；不按 type 聚合，不显示“主动工位 / 被动工位”，NPC 也不选择编号。每行只使用具体名称和实际状态，例如：

```text
诊疗位1：莉娜占用中
病床1：空闲
```

## 公告牌界面

主厅前公告牌不是建筑面板入口。`NoticeBoard.gd` 使用独立点击区和相机射线识别点击，世界标签显示当前通告的短预览；`NoticeBoardPanel` 打开时读取广场 `current_notice / reference_schedule / schedule_advisory_note`，并建立互不混用的通告草稿和参考日程草稿。通告允许任意文本；日程允许编辑开始时间、结束时间和内容，并可新增 / 删除。发布成功后刷新对应的广场状态，通告发布还会刷新世界预览；相同内容不会重复生成广播。面板关闭或打开商人 / 建筑 / NPC 等其他对象时只丢弃未发布草稿，不让 UI 自行保存另一份公告牌状态。

通告与参考日程分别由 `MemorySystem.set_plaza_notice(...)` / `set_plaza_reference_schedule(...)` 权威写入广场。发生实际变化的页面各生成一条事件，并向全站当前可接收见闻的 NPC 广播一次，不受 NPC 位于广场或室内影响；只改一页不广播另一页，相同内容不重复广播。日程见闻始终附带非强制参考备注。NPC 进入广场时不再从入场见闻重复获得公告牌两页。公告牌没有 HP、等级、工位、修复或升级，也不打开 BuildingPanel。该功能可直接在 `Main.tscn` 手动验证，因此 T0065 没有新增 GM 入口；既有 GM 广场公告 / 地点快照 / NPC 见闻入口继续复用同一底层状态。

## 商人交易界面

后门 `MerchantEntranceMarker` 只在配置到访窗口显示“商人马车已到 / 点击交易”并启用点击区。`MerchantPanel` 显示每日时段、粮食/木材/石料/铁买价、酒卖价、数量和驿站当前第纳尔/资源库存；商人离场后面板立即变为不可交易。

## 指令撰写与发布面板

只有已入伍 NPC 可以从 NPC 面板打开指令面板。该面板不显示工作、吃饭、睡觉、训练等行动选项列表，而是提供自由文本输入：

- 打开时显示该 NPC 当前 `current_order.text`；已有内容可直接修改。
- 点击“发布”时，只有新文本与原指令不同才覆盖旧指令。
- 指令变化后写入目标 NPC 的 `private` `order_assigned` 事件，并立即以非对话触发修订当前小时。
- 发布相同文本不写事件、不触发计划修订。
- 点击“关闭”不保存任何编辑，无事发生。
- UI 只提交文本和显示状态；它不直接启动行动、修改计划结果或决定 NPC 是否服从。

GM/调试信息需要能查看某 NPC 当前指令、最近修订号和发布后是否发起当前小时修订，以验证无法仅凭前端文本确认的 Prompt 注入与修订链路。

当前实现（T0703）：

- `Main/UI/OrderPanel` 绑定 `res://scripts/ui/OrderPanel.gd`，提供多行自由文本、当前修订信息、发布和关闭按钮。
- T0073 后标题显示“给 {NPC} 的指令”，输入框不显示引导 placeholder，默认说明为“驿站成员将尽量遵循守备官的指令行动。”；发布结果仍按需覆盖默认说明。
- 发布由 `NPCSystem.publish_npc_order(...)` 权威处理；面板只提交文本并显示结果。
- 守备官对话进行中时，指令面板会要求先完成或取消当前对话；打开对话面板会关闭当前指令面板，二者不会在中央重叠。
- GM 已可查看 / 发布当前指令和最近计划修订请求；Prompt 注入与真实修订结果由 T0703A/T1002/T0049 实现。

- NPCPanel 使用单栏独立“坐骑分配”子区，不挤入武器 / 策略同一行；可增长正文位于外层 `ScrollContainer`，仅在自然高度超过窗口安全高度时滚动，保证低分辨率下的对话 / 指令入口仍可达。
- 下拉框只列出“成年、未分配、物理在马厩”的具体马，并提供独立“分配 / 取消”按钮。只有已入伍且已装备主武器的 NPC 可操作；未入伍、无主武器、小马、已被他人分配或离厩时，按钮禁用并用提示说明条件。最终合法性仍由 `HorseSystem` 复验，UI 的过滤不是权威判定。
- 分配成功后显示马名、是否在厩以及战时骑乘状态；日常工作时马仍在马厩。收回主武器、取消入伍或 NPC 逃离时系统自动解除分配；更换主武器或单独卸甲不解除。UI 只刷新结果，不自行清坐骑槽或移动马匹。
- NPC 进入 `rally / combat` 后面板显示“已骑乘 / 已离厩”，退出这两种模式后显示返厩。T0038 不增加马匹承受战斗伤害的交互。

## 操作提示原则

资源消耗、前置条件、禁用原因和类似“执行前确认”的信息，默认不常驻堆在信息面板正文里；面板正文优先显示对象的当前状态。按钮、图标或具体操作入口需要在悬停时于入口旁显示提示框，说明该操作的资源消耗和条件。提示框必须保持在屏幕内，靠近屏幕边缘时应翻到按钮内侧或夹在可视区域中。建筑修复/升级是该规则的当前实现样例。

## 对话界面

对话界面突出：

- NPC 名字
- NPC 表情或情绪
- 历史对话
- 玩家输入框
- 发送按钮

可选按钮：

- 提出应征
- 赠予金钱
- 完成对话
- 取消对话
- 挂起对话

核心输入应支持自由文本，以突出 AI 玩法。

当前实现（T0701 / T0702 / T1006 / T1204A / T0028 / T0049 / T0051）：

- NPC 面板“对话”按钮打开中央对话窗口，NPC 面板保持可见；若当前指令面板已打开，会先关闭指令面板。仅打开后取消空会话不会写入事件或触发计划修改判别；开始发送或挂起后，NPC 进入 `talk_to_guard_officer` 并暂停普通行动。
- 玩家输入文本并点击发送后，守备官消息必须立即追加到历史区，再通过 `DialogSystem -> LLMBridge -> /npc/dialogue` 等待后端业务回复；开发期可使用 mock provider，Prompt 验收和演示应使用真实 provider。发送时取消目标 NPC 的其他可取消 LLM 请求并打断普通日常行动，等待回复期间历史区保留已经说出口的守备官消息。
- 玩家-NPC 对话显示“不限轮次”；NPC-NPC 先显示独立邀请判定，接受后的正式对话显示当前轮次、“无硬上限”和第 6 轮起软性收尾提示，邀请开场 / 决定在历史中显示但不增加轮次。任一正式回复都可用结束标记收尾；标记所在回复作为最后一句，不再等待对方。两类消息都走异步 `/npc/dialogue`，等待时不阻塞 Godot 主线程。
- 自主 NPC-NPC 对话不自动弹窗；只有玩家点击双方头顶气泡才进入只读旁听。旁听实时消费同一 `dialogue_id` 的开始、更新和结束快照，关闭旁听只清理 UI。等待首轮回复时，已说出口的开场内容会作为待回复内容显示，但仍只在完整回复成功后按正式规则写入对话事件。
- “同地点公开”可在首轮发送前切换；首轮发送后锁定，避免同一场对话中途改变传播规则。
- 玩家-NPC 普通对话不显示“结束后重估计划”开关。守备官主动发起与 NPC 主动交涉使用相同自主判别规则；自主 NPC-NPC 旁听和逃离挽留也不提供人为指定修订范围的控件。
- 当目标 NPC 处于集结、战斗或避战模式时，“同地点公开”默认开启且不可关闭；UI 应以禁用态显示这是战时公开对话，不允许切换成私下对话。
- “提出应征”位于“同地点公开”下方，是当前会话内的持续开关；开启后发送不会自动清除，后续消息默认继续带应征标记，直到玩家主动关闭或会话结束。T0072 后，后端返回合法 `accept` 时立即由 NPCSystem 应用入伍状态，右侧 NPC 面板在对话仍打开时就显示“已入伍：是”和可用“指令”按钮；已入伍 NPC 的“提出应征”禁用。
- 等待 NPC 回复期间，输入框仍可编辑，发送和攻击按钮禁用，但“完成对话”仍可用。此时完成会取消异步请求、丢弃迟到回复，以已经立即显示的守备官最后一句作为会话结尾，将整场会话入库并触发计划修改判别。
- “取消对话”结束会话、取消等待请求、恢复 NPC 原行动，不写 `dialogue_turn`、不产生对话见闻、不应用仍暂存的战时 / 挽留结果，也不触发计划修改判别。会话内一旦发生攻击、由 NPC 主动发起，或已经发送过应征消息，该按钮立即以半透明禁用态显示且不可点击；应征 toggle 后续关闭不解除本场锁。
- “挂起对话”只关闭窗口，不结束会话。NPC 保持 `talk_to_guard_officer` 并暂停原行动；头顶显示橙色 `↩` 会话气泡，NPC 面板【对话】按钮左上角显示橙点。点击气泡或该按钮恢复同一历史。挂起最多持续 2 个游戏小时，普通可取消会话超时自动取消；攻击、NPC 主动交涉或应征消息锁定的会话按不可取消边界自动完成并保留事实。
- 逃离挽留对话由逃离 NPC 的 NPC 面板【对话】进入；打开和挂起时都保持逃离暂停。完成或取消后恢复逃离，之后只要 5 轮额度未耗尽仍可重新开始；满 5 轮仍未挽留成功时系统自动完成、关闭面板并继续逃离。
- 攻击按钮位于发送按钮旁。普通对话中点击后先造成 10 点伤害并写入惩戒攻击事件，再请求 NPC 回复；攻击锁定取消，未等回复就完成时攻击行作为会话结尾保存并进入计划修改判别。逃离挽留中的攻击仍只由程序扣 HP、提高逃离速度并计 1 轮，不调用对话 LLM；该次会话自动完成并入库，然后恢复逃离。
- “完成对话”会提交整场有效会话为一条 `dialogue_turn`，应用会话中已返回的权威结构化意向，并调用计划修改判别。`revision_hours=[]` 表示不修改计划；非空时才修订模型选中的小时。空会话完成不伪造事件或判别。
- 如果 NPC 在对话过程中因警铃、接敌、避战、低血量自身心理判定或敌人攻击触发更高优先级模式切换，DialogSystem 强制完成已有会话、取消未完成回复并让模式切换优先生效；已经说出口的守备官消息和攻击事实不会因强制切换消失。
- 集结 / 战斗模式下与已入伍且有主武器 NPC 对话，回复结构会包含 `wartime_reaction`：`none`、`escape` 或 `morale_boost`。避战模式下与非战斗人员对话仍可使用“提出应征”；若接受但仍无主武器，程序会保持避战，只有装备主武器且场上仍有敌军时才切换进入战斗模式。

## 主动交涉气泡

当 NPC 计划中选择主动找玩家交涉时：

- NPC 头顶出现问号气泡。
- 玩家点击后打开对话界面；该点击不会先弹出 NPC 状态面板。
- 对话界面使用既有 `DialogPanel`，历史区先显示 NPC 预先确定的开场问题。
- 玩家回复后进入正常玩家-NPC 对话逻辑。
- 对话面板不提供计划重估开关；完成至少一轮有效回复后结束时，NPC 自动判别是否需要修改计划及精确阶段，非空才执行第二次计划修订调用。
- 若 1 游戏小时内无人点击，问号气泡自动消失；该超时没有实际对话内容，不调用对话判别层，而是直接修订当前小时。

当前实现（T0705）：

- 问号气泡由 `NPC.gd` 运行时创建为 `ProactiveTalkBubble`，主动交涉有效时显示。
- 触发入口当前主要是 GM 面板“主动交涉”按钮或 `start_proactive <npc_id> <text>` 命令；正式计划系统生成主动意图仍归后续计划任务。

## 战斗信息

战斗时需要显示：

- 当前波次
- 敌人数量概览
- 我方参战人数概览
- 关键战场公开事件
