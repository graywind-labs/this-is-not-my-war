## T0315 建筑完工与小马命名弹窗

- 正式 Main 使用同一个串行提示队列承接建筑修复完成、建筑升级完成和小马待命名；当前弹窗未确认时，新结果排队等待，不互相覆盖。
- 建筑窗口居中显示“XX修复完成。”或“XX升级完成。”，唯一主按钮为“确认”。窗口只消费 BuildingSystem 已提交的真实结果，不读取进度条猜完成。
- 小马窗口正文固定为“在精心照料下，一匹小马出生了！你给他命名为”，下方 LineEdit 预填匹配模板的默认名、选中全文并获得焦点，`max_length=5`，主按钮为“确定”。玩家不修改即可保留预设名。
- 空白名、超过 5 字、重名或失效请求都不能关闭命名窗；可见校验文本解释原因。窗口关闭请求会保留待命名事务并要求先命名，不能用关闭动作绕过正式入库边界。
- 命名窗只调用 HorseSystem 的确认接口；成功后才关闭并继续下一条提示。它不创建马匹、不改马槽、不广播事件，也不直接刷新其他马名组件。

## T0311-T0314 世界数值反馈与制造收获完整合同

### 总体边界

- 世界反馈只投影权威系统已经提交的实际变化。UI 不监听绝对库存后自行猜测差值，不预支工作进度、治疗进度、伤害、熟练度、马匹生态或制造成品。
- 统一反馈事件至少包含锚点类型 / id、必要的世界坐标回退、频道、替换规则和条目数组；每个条目携带正式 id / 名称、实际带符号增量、颜色语义和可用图标。表现层不得通过反馈 payload 反写任何玩法状态。
- 有正式图标时显示图标与 `+/-` 数量；没有图标时显示正式名称与数量。禁止使用系统 emoji 代替资源或收获图标，避免重复出现缺字方框。

### 颜色、文字与动画

| 类型 | 颜色 | 示例 |
|---|---|---|
| 资源消耗 | 低饱和灰 | 铁图标 `-2`、`粮食 -1` |
| 资源 / 物品获得 | 暖白 | 粮食图标 `+2`、餐食图标 `+2` |
| HP 伤害 | 暗红 | `-12` |
| HP / 额外 HP 恢复 | 低饱和绿 | `+3`、`额外HP +1` |
| 熟练度 / 经验 / 技能点 | 低饱和蓝 | `打铁 +1　经验 +1` |
| 饱食 / 疲劳 / 成长 / 繁育概率 | 暖白 | `饱食 +30`、`疲劳 -20`、`成长 +0.1%` |
| 失败原因 | 琥珀色短文，不带假数值 | `缺少铁`、`仓库已满` |

- 每组反馈总共显示 2 个现实秒：前 1.2 秒稳定可读，后 0.8 秒向上移动约 `32–40px` 并逐渐透明。生命周期不读取玩家 `x1/x2/x4` 或逻辑游戏秒；暂停后已经出现的反馈仍按现实时间结束。
- 同一次权威提交合并为一个反馈组，默认最多三行；超过时按资源、状态、成长类别合并。普通反馈同一锚点最多保留两个组，旧组提前上移让位。
- 伤害使用独立替换频道；同一目标的新伤害立即删除旧红字并重新开始 2 秒动画。治疗 / 成长不与伤害共用替换槽。
- 对象位于相机后方或屏幕外时不显示，不把反馈钉在屏幕边缘。反馈保存最后有效世界坐标；敌人或其他目标在结算后同帧移除时仍能完成本次淡出。

### 锚点与现有头顶层级

- 我方 NPC 继续保留 T0301 的姓名 `2.08m`、血条 `2.62m`、思考 / 主动交涉 `2.95m`、逃离 / 对话 `3.12m`、情绪 `3.72m`。站立反馈基准位于约 `4.25m`；骑乘按实际骑手高度继续上移；昏迷使用倒地身体中心上方的动态锚点。
- 敌军反馈位于其姓名和血条之上。马匹现有姓名位于 `2.15m`，反馈基准约 `2.75m`。器械和建筑使用各自高于名称、血条和交互图标的 `FeedbackAnchor`。
- 城墙或大型建筑优先使用实际命中世界坐标；没有命中坐标时才使用建筑反馈锚点。反馈为屏幕空间 Control，但位置始终来自正式世界对象或权威结果。

### 普通工作、吃饭、睡觉与成长

- 普通工作只在完整周期成功后读取并显示实际 `input_resources`、实际 `output_resources` 和本轮成长结果。资源不足、仓库容量不足、工位失败、行动中断或零变化都不显示成功数字；需要提示时使用琥珀色失败短文。
- 铁匠铺 / 工械坊一个周期只提交一个制造阶段，不保证同时有输入和成品。中间阶段显示本阶段真实扣料与暖白“阶段完成 N/M”；零材料收尾阶段不伪造消耗。最终阶段在 T0314 后显示“物品 `+1 待收取`”，不得显示为正式库存获得。
- 吃饭沿用现有权威时点：成功开始用餐并实际扣除所选粮食 / 餐食后显示灰色消耗；用餐过程中每次饱食实际增加时，在同一需求替换频道更新白字。行动中断不退还已经消耗的食物，也不补发尚未发生的饱食恢复。睡眠只显示实际减少的疲劳，并使用同一需求替换频道避免高速时堆字。普通工作过程中的常规疲劳 / 饱食消耗继续由状态条表达，不在每个模拟步长刷字。
- `increase_npc_skill(...)` 的实际结果统一显示熟练度、经验和新技能点；达到 100、非法技能或实际增量为零时不显示。一次成长合并为一行蓝字，例如“打铁 +1　经验 +1　技能点 +1”，既避免重复表现，也为普通工作保留“资源消耗 / 资源获得 / 成长”最多三行的稳定结构。

### 战斗、治疗、建筑与器械

- NPC、敌军、马匹、器械和建筑受击显示 `hp_before - hp_after`，不显示原始攻击力、请求伤害或超过剩余 HP 的溢出值；零 HP 差不显示红字。
- 坐骑分伤在骑手和对应实体马匹上分别显示自身损失，不在骑手处重复总伤害。范围伤害按每个真实目标分别生成。
- 昏迷自然恢复、协助治疗、诊所治疗和建筑修复只在 HP 真正增加时显示绿色增量。连续小额治疗在短现实时间内合并；NPC 跨过阈值复苏时仍保留 T0310 居中弹窗，回血字不能代替复苏提示。
- T0312 已落地：伤害使用 `damage` 替换频道；治疗使用 `healing` 频道并在 `0.45s` 内合并。NPC `4.25m`、敌军 `2.95m`、马匹 `2.75m`、建筑入口 `3.0m`、器械部署位 `2.35m` 为缺少精确命中点时的默认偏移；实际碰撞点只额外抬高约 `0.25–0.35m`。目标移除后沿结算坐标完成动画，不转移到攻击者或宿主建筑。
- 当前 DefenseDeviceSystem 没有器械恢复权威入口；绿色器械恢复只保留为“存在适用权威结算时接入”的合同，不允许 Presenter 或 BuildingSystem 代替器械回血。

### 马匹生态聚合

- 马匹进食完成时成组显示灰色粮食消耗与白色饱食恢复；自然回血可成组显示绿色 HP 和实际饱食代价；照料显示绿色额外 HP、白色成长与繁育概率。
- 连续浮点变化按玩家可见精度积累：HP / 饱食至少 `1`，成长 / 繁育概率至少 `0.1%` 才发出反馈。多匹马各自在自身锚点显示，不把整个马厩的生态变化堆到养马人头顶。
- T0313 已落地：进食组使用 `horse_feeding` 逐马替换频道，粮食只在 ResourceSystem 成功原子扣除后显示，饱食使用上限钳制后的实际增加量；缺粮等待没有成功组。自然回血只把本次回血支付的饱食计入聚合，不显示日常厩内 / 厩外维护消耗。
- `horse_ecology` 在一次 HorseSystem 外层模拟推进结束时按马刷新。HP、回血饱食和额外 HP 只消费完整 `1` 点，成长 / 繁育概率只消费完整 `0.1%`，小数余量保留；新组替换同马旧生态组。成长抬高自然上限并同步增加当前 HP 时，绿色 `HP +N` 与白色成长同组；照料额外 HP 另列绿色“额外HP”。
- 只有物理在厩马参与照料成长、额外 HP 和繁育；离厩马仍可按原规则自然回血。繁育成功 / 冷却清除未显示概率余量，死亡清除该马全部余量，避免之后出现过期正数。暂停不推进 HorseSystem，已出现组仍按 Presenter 的现实 2 秒生命周期结束。

### 铁匠铺 / 工械坊暂存与收获

- 制造成品完成后先进入对应建筑的 `pending_outputs`，不调用正式库存增加接口。阶段材料照常原子扣除，项目阶段归零，当前目标保留并可继续生产下一件。
- 待收取状态按建筑和具体 `item_*` id 保存，可同时累积多种物品与多个数量。换目标、工作中断、NPC 离岗和建筑受损不清除已完成成品；后续若设计掠夺 / 损毁必须另立权威任务。
- 待收取物品不计入 HUD 装备 / 器械正式数量，不能装备、分配或部署。项目快照继续区分正式 `stock_amount` 与待收取数量；事件使用 `pending_output_resources`，不能用 `output_resources` 暗示已经入库。
- 建筑存在待收取成品时，上方显示项目内置小手 SVG 的约 `44×44px` 圆形按钮，右上角显示总件数徽标；新成品只触发一次轻微放大回弹，不持续闪烁。Tooltip 为“收取XX成品（N）”。BuildingPanel 同步提供“待收取：N件”和同一入口，按钮离屏时仍可找到。
- 点击收获按钮打开居中弹窗，标题为“铁匠铺待收取成品”或“工械坊待收取成品”。内容复用装备选择界面的纯图标密度：每件成品对应一个 `68×68px` 无边框图标，同类有几件就重复几个图标；不常驻显示名称、数量或 `×N` 徽标，Tooltip 只显示该件物品的正式名称，正文不展示内部 id。
- 关闭弹窗不改变暂存。点击“收下”时 CraftingSystem 读取点击瞬间的全部暂存内容并原子转入正式库存；成功后关闭、刷新 HUD 并在清空时移除小手按钮。弹窗打开期间新增成品应实时刷新，并由随后点击的“收下”一并收取。
- 当前具体装备 / 器械没有仓库容量限制；接口仍须保留全量原子提交语义。未来若加入容量限制，失败时全部暂存保持不变并显示原因，不能部分入库或丢失。

### 不纳入重复飘字的操作

- 商人买卖、装备穿脱、器械部署已有直接面板回执，不额外在世界中重复同一结果。祈祷虔诚可在后续按整数阈值接入暖白 / 低饱和金色反馈，但不得逐逻辑步长刷字。
- 反馈系统不写入 NPC 事件库或见闻库；相关工作、伤害、治疗、制造事件仍由原权威系统和 MemorySystem 记录，视觉反馈不是第二套事实。

## 公告牌界面

主厅前公告牌不是建筑面板入口。`NoticeBoard.gd` 使用独立点击区和相机射线识别点击，世界标签显示当前通告的短预览；`NoticeBoardPanel` 打开时读取广场 `current_notice / reference_schedule / schedule_advisory_note`，并建立互不混用的通告草稿和参考日程草稿。通告允许任意文本；日程允许编辑开始时间、结束时间和内容，并可新增 / 删除。发布成功后刷新对应的广场状态，通告发布还会刷新世界预览；相同内容不会重复生成广播。面板关闭或打开商人 / 建筑 / NPC 等其他对象时只丢弃未发布草稿，不让 UI 自行保存另一份公告牌状态。

通告与参考日程分别由 `MemorySystem.set_plaza_notice(...)` / `set_plaza_reference_schedule(...)` 权威写入广场。发生实际变化的页面各生成一条事件，并向全站当前可接收见闻的 NPC 广播一次，不受 NPC 位于广场或室内影响；只改一页不广播另一页，相同内容不重复广播。日程见闻始终附带非强制参考备注。NPC 进入广场时不再从入场见闻重复获得公告牌两页。公告牌没有 HP、等级、工位、修复或升级，也不打开 BuildingPanel。该功能可直接在 `Main.tscn` 手动验证，因此 T0065 没有新增 GM 入口；既有 GM 广场公告 / 地点快照 / NPC 见闻入口继续复用同一底层状态。

## 商人交易界面

旧后门 `MerchantEntranceMarker` 已不再作为交易入口。实体行商马车真实停靠后才显示车斗上方的小型羊皮纸钱袋牌和短“交易”标签并启用点击区。`MerchantPanel` 显示每日时段、粮食/木材/石料/铁买价、酒卖价、数量和驿站当前第纳尔/资源库存；商人离场后面板立即变为不可交易。

## 指令撰写与发布面板

只有已入伍 NPC 可以从 NPC 面板打开指令面板。该面板不显示工作、吃饭、睡觉、训练等行动选项列表，而是提供自由文本输入：

- 打开时显示该 NPC 当前 `current_order.text`；已有内容可直接修改。
- 点击“发布”时，只有新文本与原指令不同才覆盖旧指令。
- 指令变化后写入目标 NPC 的 `private` `order_assigned` 事件，并立即以非对话触发修订当前小时。
- 发布相同文本不写事件、不触发计划修订。
- 点击“关闭”不保存任何编辑，无事发生。
- UI 只提交文本和显示状态；它不直接启动行动、修改计划结果或决定 NPC 是否服从。

GM/调试信息需要能查看某 NPC 当前指令、最近修订号和发布后是否发起当前小时修订，以验证无法仅凭前端文本确认的 Prompt 注入与修订链路。

当前实现（T0703）：

- `Main/UI/OrderPanel` 绑定 `res://scripts/ui/OrderPanel.gd`，提供多行自由文本、当前修订信息、发布和关闭按钮。
- T0073 后标题显示“给 {NPC} 的指令”，输入框不显示引导 placeholder，默认说明为“驿站成员将尽量遵循守备官的指令行动。”；发布结果仍按需覆盖默认说明。
- 发布由 `NPCSystem.publish_npc_order(...)` 权威处理；面板只提交文本并显示结果。
- 守备官对话进行中时，指令面板会要求先完成或取消当前对话；打开对话面板会关闭当前指令面板，二者不会在中央重叠。

## 操作提示原则

资源消耗、前置条件、禁用原因和类似“执行前确认”的信息，默认不常驻堆在信息面板正文里；面板正文优先显示对象的当前状态。按钮、图标或具体操作入口需要在悬停时于入口旁显示提示框，说明该操作的资源消耗和条件。提示框必须保持在屏幕内，靠近屏幕边缘时应翻到按钮内侧或夹在可视区域中。建筑修复/升级是该规则的当前实现样例。

- NPC 面板“对话”按钮打开中央对话窗口，NPC 面板保持可见；若当前指令面板已打开，会先关闭指令面板。仅打开后取消空会话不会写入事件或触发计划修改判别；和平工作模式开始发送或挂起后，NPC 进入 `talk_to_guard_officer` 并暂停普通行动。`rally / combat / avoid_combat` 战时对话只建立并行会话，不改写或暂停战斗行动。
- 玩家输入文本并点击发送后，守备官消息必须立即追加到历史区，再通过 `DialogSystem -> LLMBridge -> /npc/dialogue` 等待后端业务回复；开发期可使用 mock provider，Prompt 验收和演示应使用真实 provider。发送时取消目标 NPC 的其他可取消 LLM 请求并打断普通日常行动，等待回复期间历史区保留已经说出口的守备官消息。
- 玩家-NPC 对话显示“不限轮次”；NPC-NPC 先显示独立邀请判定，接受后的正式对话显示当前轮次、“无硬上限”和第 6 轮起软性收尾提示，邀请开场 / 决定在历史中显示但不增加轮次。任一正式回复都可用结束标记收尾；标记所在回复作为最后一句，不再等待对方。两类消息都走异步 `/npc/dialogue`，等待时不阻塞 Godot 主线程。
- 自主 NPC-NPC 对话不自动弹窗；只有玩家点击双方头顶气泡才进入只读旁听。旁听实时消费同一 `dialogue_id` 的开始、更新和结束快照，关闭旁听只清理 UI。等待首轮回复时，已说出口的开场内容会作为待回复内容显示，但仍只在完整回复成功后按正式规则写入对话事件。
- “公开”可在首轮发送前切换；首轮发送后锁定，避免同一场对话中途改变传播规则。
- 玩家-NPC 普通对话不显示“结束后重估计划”开关。守备官主动发起与 NPC 主动交涉使用相同自主判别规则；自主 NPC-NPC 旁听和逃离挽留也不提供人为指定修订范围的控件。
- 当目标 NPC 处于集结、战斗或避战模式时，“公开”默认开启且不可关闭；UI 应以禁用态显示这是战时公开对话，不允许切换成私下对话。
- “提出应征”位于“公开”下方，是当前会话内的持续开关；开启后发送不会自动清除，后续消息默认继续带应征标记，直到玩家主动关闭或会话结束。T0072 后，后端返回合法 `accept` 时立即由 NPCSystem 应用入伍状态，右侧 NPC 面板在对话仍打开时就显示“已入伍：是”和可用“指令”按钮；已入伍 NPC 的“提出应征”禁用。
- 等待 NPC 回复期间，输入框仍可编辑，发送和攻击按钮禁用，但“完成对话”仍可用。此时完成会取消异步请求、丢弃迟到回复，以已经立即显示的守备官最后一句作为会话结尾，将整场会话入库并触发计划修改判别。
- “取消对话”结束会话、取消等待请求、恢复 NPC 原行动，不写 `dialogue_turn`、不产生对话见闻、不应用仍暂存的战时 / 挽留结果，也不触发计划修改判别。会话内一旦发生攻击、由 NPC 主动发起，或已经发送过应征消息，该按钮立即以半透明禁用态显示且不可点击；应征 toggle 后续关闭不解除本场锁。
- “挂起对话”只关闭窗口，不结束会话。NPC 保持 `talk_to_guard_officer` 并暂停原行动；头顶显示橙色 `↩` 会话气泡，NPC 面板【对话】按钮左上角显示橙点。点击气泡或该按钮恢复同一历史。挂起最多持续 2 个游戏小时，普通可取消会话超时自动取消；攻击、NPC 主动交涉或应征消息锁定的会话按不可取消边界自动完成并保留事实。
- 逃离挽留对话由逃离 NPC 的 NPC 面板【对话】进入；打开和挂起时都保持逃离暂停。完成或取消后恢复逃离，之后只要 5 轮额度未耗尽仍可重新开始；满 5 轮仍未挽留成功时系统自动完成、关闭面板并继续逃离。
- 攻击按钮位于发送按钮旁。普通对话中点击后先造成 10 点伤害并写入惩戒攻击事件，再请求 NPC 回复；攻击锁定取消，未等回复就完成时攻击行作为会话结尾保存并进入计划修改判别。逃离挽留中的攻击仍只由程序扣 HP、提高逃离速度并计 1 轮，不调用对话 LLM；该次会话自动完成并入库，然后恢复逃离。
- “完成对话”会提交整场有效会话为一条 `dialogue_turn`，应用会话中已返回的权威结构化意向，并调用计划修改判别。`revision_hours=[]` 表示不修改计划；非空时才修订模型选中的小时。空会话完成不伪造事件或判别。
- 如果 NPC 在对话过程中因警铃、接敌或避战进入 `rally / combat / avoid_combat`，已有守备官会话和未完成回复继续保留，窗口语境随权威模式更新，战斗动作独立推进。昏迷、实际逃离和低血量自身心理判定仍保留各自既有的高优先级会话边界；已经说出口的守备官消息和攻击事实不会因这些边界消失。
- 集结 / 战斗模式下与已入伍且有主武器 NPC 对话，回复结构会包含 `wartime_reaction`：`none`、`escape` 或 `morale_boost`。避战模式下与非战斗人员对话仍可使用“提出应征”；若接受但仍无主武器，程序会保持避战，只有装备主武器且场上仍有敌军时才切换进入战斗模式。

## 主动交涉气泡

当 NPC 计划中选择主动找玩家交涉时：

- NPC 头顶出现问号气泡。
- 玩家点击后打开对话界面；该点击不会先弹出 NPC 状态面板。
- 对话界面使用既有 `DialogPanel`，历史区先显示 NPC 预先确定的开场问题。
- 玩家回复后进入正常玩家-NPC 对话逻辑。
- 对话面板不提供计划重估开关；完成至少一轮有效回复后结束时，NPC 自动判别是否需要修改计划及精确阶段，非空才执行第二次计划修订调用。
- 若 1 游戏小时内无人点击，问号气泡自动消失；该超时没有实际对话内容，不调用对话判别层，而是直接修订当前小时。

当前实现（T0705）：

- 问号气泡由 `NPC.gd` 运行时创建为 `ProactiveTalkBubble`，主动交涉有效时显示。
- 触发入口当前主要是 GM 面板“主动交涉”按钮或 `start_proactive <npc_id> <text>` 命令；正式计划系统生成主动意图仍归后续计划任务。

## 战斗信息

战斗时需要显示：

- 当前波次
- 敌人数量概览
- 我方参战人数概览
- 关键战场公开事件
- 昏迷 NPC 提示
- 建筑受损提示

战斗信息中的公开事件应来自广场即时广播与 NPC 已接收见闻。UI 只展示事件摘要，不决定事件是否公开，也不让后来进入广场的 NPC 自动获得过去事件。
