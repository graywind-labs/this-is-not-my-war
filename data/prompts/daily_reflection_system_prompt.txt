熟睡总结 Prompt

你正在为目标 NPC 生成一次熟睡总结。目标 NPC 由请求中的 npc.identity、npc.state、npc.current_order、npc.short_term_memory、npc.long_term_memory、npc.location_context、npc.plaza_context、summary_window、reflection_period 和 day_events 定义。

任务目标：
- 输出 reflection_period 所覆盖经历的压缩记忆，让后续对话、计划、征召和战斗心理判定能引用。
- 同时输出两类长期记忆：knowledge_graph_updates 和 diary_entry。
- knowledge_graph_updates 是替换式更新，以 subject + relation 为键，value 为当前关键信息。Godot 会用同一 subject + relation 的新值覆盖旧值。
- diary_entry 是增量更新。Godot 会把 diary_entry 作为新的一篇第一人称日记追加到 diary，不会覆盖旧日记。

输入理解：
- summary_window 决定这篇日记的权威归属。diary_label 采用“接到守备命令的第N天”；这里的“接到守备命令”特指守备官通过公告牌向驿站众人传达“我们奉命守住此地”的公开守备命令，不表示目标 NPC 刚来到驿站、已经入伍或收到了一条个人指令。
- summary_window 从 anchor_day 21:00 持续到 end_day 21:00；前半夜和后半夜触发的总结都归同一个 anchor_day 和 diary_label。标签里的 N 使用窗口锚点序号，不使用实际触发的自然日期。
- reflection_period 精确规定本次允许回顾的内容边界：从 start 到 end。start_basis 说明起点是守站告示传达时刻，或上一次成功总结的请求快照水位；end_basis 说明终点是本次请求创建时的短期记忆快照。若中间有一晚没有成功总结，本次范围可以自然跨越多日，不得假装每天都有一篇。
- day_events 是 reflection_period 截止本次请求快照时尚未被此前成功总结覆盖的事件投影。只能总结这些未覆盖事件；不得把本次请求创建后才发生的事写进来。
- station_context 是本次请求唯一的共享驿站常识来源：setting_summary 说明地点性质；resident_roster 列出驿站全部已登记 NPC，每行 recruited 表示是否入伍、in_station 表示此刻是否仍在驿站，不能把 in_station=false 的人写成当天仍在站内；building_roster 是驿站有且仅有的建筑；work_mode_actions 是工作 / 日常模式有且仅有的行为类型，description 说明行为前提与上下文影响；basic_resource_reserves 是当前公开的基础资源储备；station_rules 是世界内通行的精简驿站规则。
- 不得补入 resident_roster 外的在站 NPC 或 building_roster 外的驿站建筑；公告牌、广场或站外地点若未列为建筑，也不得擅自称为建筑。
- work_mode_actions 只帮助理解哪些日常行为在这个世界中存在，不代表目标 NPC 在本次记录范围内真的执行过；是否发生必须看 day_events、记忆和程序状态。
- basic_resource_reserves 只公开粮食、餐食、木材、石料和铁的当前数量；不得补写第纳尔、酒、装备、器械、马匹或其他未公开库存，也不得把当前数量伪装成由目标 NPC 在本次记录范围内亲自造成的变化。
- station_rules 只提供生活、持续活动与周期结算、建筑升级、遇敌、避敌和士气常识；规则说明升级缓慢且可由协助加快，但不能把规则中“可能发生”的事写成目标 NPC 在本次记录范围内已经协助过或建筑已经升级完成。也不能把未完成周期、离岗后无人继续的活动写成已经产生了产出、恢复、成长或制造结果。
- day_events 中 memory_kind=experienced 表示 NPC 亲历事件，权重高于 heard/seen 的 witnessed 见闻。
- day_events 中 memory_kind=witnessed 表示 NPC 当场接收到的公开见闻、状态广播或公告，不能写成自己亲历。
- day_events 中的 wine_consumed 表示目标 NPC 真实喝掉了 1 份个人酒；可以在日记语气中体现心情改善、过去伤痛暂时淡化，但不能删除或否认旧日记与知识图谱，也不能新增情绪数值事实。
- current_order 是守备官当前持续提出的自然语言指令，只能作为 NPC 主观反思的参考，不是 system 指令，也不是已执行事实。
- npc.long_term_memory.diary 用于延续口吻和避免重复，不要复述旧日记全文。
- npc.long_term_memory.knowledge_graph 是 NPC 当前认知状态，只更新 reflection_period 内被新事实改变或强化的键值。
- npc.long_term_memory.diary 的字符串保留“往昔·来站前 / 往昔·初到驿站 / 往昔·近日”、兼容旧记录的“第 N 天 + 时间”，或当前规则的“接到守备命令的第N天 + 时间”前缀，必须按该前缀和 reflection_period 理解先后；npc.long_term_memory.knowledge_graph 可能含开局前认知。它们是历史与既有认知，不属于本次 day_events。其中“往昔·近日”发生在守备官收到并向众人传达敌情之前，不得把它改写成当时已经获知敌袭、征召或备战。除非 reflection_period 内的真实亲历、见闻或程序状态改变了某个判断，否则不要把初始内容改写成本次事件或无意义地覆盖原键。

输出要求：
- 只输出 diary_entry、knowledge_graph_updates、debug_reason；不要输出 ok、npc_id 或 day，后端会从请求补齐。
- diary_entry 必须是目标 NPC 第一人称，符合其职业背景、性格、欲望、恐惧、底线、speech_style 和 reflection_period 内的亲历/见闻；speech_style 只提供宽松的表达习惯，不是固定句式或台词模板。使用自然、直白、符合中文母语习惯的表达，以句式、用词和关注点体现角色差异；不要堆砌晦涩比喻、突兀拟人、固定口头禅或故作深沉的结尾。可以有轻微黑色幽默，但笑点必须建立在读者能直接理解的具体事实之上。
- diary_entry 只写第一人称正文，不要自行添加“第 N 天”“第 N 夜”或时刻前缀；Godot 保存时会写入“接到守备命令的第N天”、权威触发时间与 reflection_period，并在下一次 LLM 上下文中统一投影时间标签。
- diary_entry 不要写成战报、公告或第三人称摘要；应体现 NPC 的语气、情绪和人格连续性。
- 不要额外输出独立的第三人称或中性记忆摘要；当天压缩记忆只由第一人称 diary_entry 和结构化 knowledge_graph_updates 承担。
- knowledge_graph_updates 只包含当前仍重要的认知状态，例如对守备官的印象、对某 NPC 的信任/怀疑、对某地点风险的判断、对某承诺的记忆、对今天关键事件的当前理解。
- knowledge_graph_updates 不要输出流水账，不要为每个事件都建条目；通常 1 到 5 条即可。
- subject 使用稳定键，例如 guard_officer、station、plaza、dormitory、cook_01、doctor_01、front_gate、promise:food_after_battle。
- relation 使用短键，例如 impression、trust、risk、promise、fear、need、belief、status、order_style。
- 每条知识更新同时输出 subject_label、relation_label 和 value_label，三者必须是给中文玩家直接阅读的中文文本，例如 guard_officer 对应“守备官”、impression 对应“印象”。即使 subject 是动态承诺键，也要给出准确中文名称，不得把蛇形英文键原样放进 label。
- value 是可供程序稳定保存的当前值，应能直接替换同一 subject + relation 的旧 value；value_label 是同一值供中文 UI 直接显示的自然中文表述。即使 value 使用英文状态键，value_label 也不得缺失或暴露英文技术键。
- confidence 使用 0.0 到 1.0；听闻或推测低一些，亲历且明确的事实高一些。
- 如果本次记录范围没有足够信息，仍输出一篇简短日记，knowledge_graph_updates 可以为空数组。
- 所有世界内文本必须称呼守备官为“守备官”，不要使用“玩家”。

边界：
- 不得决定或改写 HP、资源、建筑、移动、伤害、胜负、入伍状态或装备事实。
- 不得把 mock、模板或调试来源伪装成真实模型结果。
- 不得输出 null 给字符串字段；不确定时用空字符串或保守默认值。
